# 四腿永续腿挂同侧最优价，并用有限改价替代让出价差

Boros 两条利率腿建立后需要建立对应永续双腿。旧报价策略把 maker 挂在同侧最优价**之外一个买卖价差**（`2*bid − ask`），盘口不动时几乎不可能成交，用户选择 maker＋hedge 却经历长时间零成交，最后两条腿都付 taker 手续费。现在的决定是：**只对明确来自四腿建仓后永续对冲流程的新 deal**，初始挂同侧最优价、保持 post-only，并在落后至少两个 tick 且距上次挂单至少十五秒时自动改价，上限二十次，默认等待三十分钟，到期后按原 converting 路径以 taker 补齐。普通永续双腿、单腿、平仓与存量 deal 的策略一个字都不改。

## Considered Options

- **保持旧行为，改用申请 maker 费率或选择 maker 返佣更高的交易所**：被否，结算周期与费率结构不可控，且首次 maker venue 选择已经按手续费率比较过。
- **两条永续都挂 maker**：被否，会让已确认成交的 maker 腿长时间不被对冲。
- **用资金费率与下次结算时间约束等待窗口，并设置资金费损失预算**：被否。资金费过覆盖、永续价格净敞口和博罗斯隐含 APR 浮盈亏是三种不同状态，资金费结算时点无法约束它们；用户明确撤回该项。
- **加双腿入场基差检查**：被否，属于对交易经济性的二次判断，用户要求不在本次引入。
- **只在盘口不动够久后单次追价**：被否，改价次数与时间何时终止不可解释；改为有次数上限、有最小间隔、有明确落后阈值的固定规则。

## Consequences

- 入场成本会随追价和跨资金费结算而改变，这是已接受的取舍；三十分钟是等待窗口，不是成交保证，也不是风险损失上限。
- 抢价差位置使成交和**手续费节省的意义**都提高，但结算价同时更差。这不是「更优执行」，是不同取舍：旧策略省手续费但常不成交，新策略更可能成交但更接近对手价。
- 挂同侧最优价位于盘口最容易被穿越的位置，post-only 拒绝会成为高频事件。原有实现把 post-only 会 cross、taker clip 被拒、taker clip 白打三类失败计在**同一个**预算上，共用一个上限并统一导向「诚实部分成交」。新策略下这种合并会掐断用户期望的 taker 补齐路径，所以 post-only 拒绝需要独立预算并导向 converting。**这不构成对普通永久双腿、单腿、平仓及存量 deal 的旧预算的修改。**
- `price_policy` 一个字段同时承担「来自四腿流程」与「如何报价」两件事：新增取值 `'best'`。代价是任何能发出该取值的调用方都会启用新策略，因此范围隔离落在 UI 与创建路径上，而不在一个独立的来源字段上。这也意味着该字段的值不得在现有取值上原地重定义——旧 `'touch'` 的含义（价差外）保持不动。
- 改价次数与上次挂单时刻成为持久化事实，且新列要能被旧库打开：现有迁移逻辑只探测 `orders` 表，新增 `pair` 列的路径需要单独建立，并在读取时对缺失列兜底，否则改价上限会静默失效。
