# Boros 只挂一条 Maker 腿，其余资金费腿按成交量吃单补齐

决策日期：2026-10-24。

Boros 两条资金费腿目前都以吃单成交。复盘显示，在当前规模（单笔约 $10k 名义）下，Boros 成本的主要部分是吃单手续费与买卖价差，不是吃穿盘口深度：ETH HL/Gate 12-25 在 2、4、5 ETH 的成交利率完全相同，把单子拆成多批 IOC 几乎不省钱。价差只有挂单才能拿到。

现在的决定：**新开仓与展期都可以使用 Boros Maker，但每次只有一条 Maker 腿，其余资金费腿作为补齐腿，按 Maker 已确认的成交数量吃单补齐。** 补齐优先于利润。是否采用只按确定节省的 taker 手续费评估，挂单的成交价改善在实际成交后统计，不计入事前门槛。

- **Maker 腿的选择**：目标规模下买卖价差（吃单成交价相对中间价）较大的一侧。在 deal 创建时确定并持久化。
- **新开仓的补齐**：每确认一笔 Maker 成交（累计满 Boros 最小下单额），立即以吃单补齐同等数量。补不上时放宽一次容差重试，仍失败就告警、隔离。
- **展期的补齐**：Maker 腿只能是一条新仓腿。每确认一笔成交，把同等数量的另外三条腿（平两条旧腿、开另一条新腿）放进一个原子批次补齐。旧仓到期前 7 天开始挂单，到期前 3 天停止，剩余部分走原子吃单展期。
- **挂单规则**：只用 post-only，挂在同侧最优价，有限次数改价，规则与 ADR 0001 一致。启用门槛、改价上限、等待时限和补齐时限是可调参数，不在本 ADR 固定。
- **永续腿**：Boros 全部完成或回退完成后，再按现有永续流程建立。

## Considered Options

- **两条 Boros 腿都挂 Maker**：被否。两笔挂单未来的成交互不同步，资金费缺口与过覆盖的数量和持续时间都无法控制。
- **展期时让旧仓平仓腿挂 Maker**：被否。先平旧会形成资金费缺口。改由新仓腿挂单，敞口只是不超过一笔成交量、持续一个补齐周期的过覆盖。
- **分批 IOC 吃单，替代挂单**：被否。在当前规模下吃单成本主要是价差，拆单省不掉。
- **补齐受利润下限约束，低于下限就不补**：被否。不补齐会让利率敞口长期存在，这比补齐时利差差一点的代价更大。

## Consequences

- **有意偏离 ADR 0001**：ADR 0001 拒绝在永续挂单上加经济性检查。Boros Maker 要加：补齐腿的可成交利率比 deal 创建时变差超过约 5bp，就撤掉挂单，剩余转吃单。原因是 Boros 一条腿省下的手续费只是年化约 5bp 乘以剩余期限，余量太小，不加保护的话逆向选择会吃光节省。
- **展期不再全程原子**：只有 Maker 腿是非原子的。词汇表中"原子展期"的定义不变，只是使用 Maker 的展期不再满足它。
- **撤单需要撤净确认**：回退到吃单之前，必须拿到撤净确认（挂单已不在订单簿，撤单期间的新增成交已核清），不能只看撤单请求是否发出。挂单在终端离线时仍可能成交，所以正常停机前要先撤单并确认撤净；异常退出后，重启第一件事是对账并补齐。
- **持久化与恢复**：Boros 不提供交易所级别的 clientOrderId 去重，挂单的登记、查证和恢复必须纳入 deal 引擎的单写者与写前登记约束，不能沿用现有面板的进程内去重。
- **零星成交**：不足 Boros 最小下单额的成交先累积，满额再补齐。deal 结束时剩下的部分记为过覆盖尾差并展示。
- **验证顺序**：先用一笔约 $6k 的真实新开仓验证完整流程（Maker 腿只挂一次、不改价），通过后才在展期上使用。实盘验证需要用户明确同意。
