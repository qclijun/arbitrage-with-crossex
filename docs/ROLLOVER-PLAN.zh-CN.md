# 临近到期的展期执行计划

适用场景：已有四腿资金费套利仓位，Boros 旧仓临近到期，拟保留永续并切换至下一期。2026-10-05 按审核访谈确认的决策修订；策略边界已确认，实际执行仍未就绪。本文不授权下单、转账或修改监控配置。

依据：[日常风险清单](DAILY-RISK-CHECKLIST.zh-CN.md)、[指标契约](RISK-MONITOR-CONTRACTS.md)、[审核记录](ROLLOVER-REVIEW.zh-CN.md)、[领域词表](../GLOSSARY.md)。未查询实时账户、报价或最新官方成交规则；这些事实及未填写参数均为 UNKNOWN。

## 1. 已确认的策略边界

- **风险优先**：降低失配与清算风险优先于维持规模、节省手续费和收益目标。允许部分展期或全部退出，不为完成全量而突破预算。
- **不追加资金**：新增 ETH、USDT、USDC 均为零；不新增借款，不把未到账或未释放资金计入余额。已有负债及可能由仓位损失、结算产生的借款仍须检查，不能把“不借款”当成平台不会自动计息。
- **价格中性**：常规展期保持两条永续方向和数量不变。紧急减仓允许受限价格净敞口，但必须先确定数量、时间和美元损失上限。
- **默认路径**：使用经核验的 Boros 专用批处理展期；不可用时暂停新增、准备缩仓或退出。人工逐腿替换、到期后单独开新仓须另审完整方案，本计划不将其作为临场备用。
- **收益准入**：扣除实际成本后的净收益须覆盖额外执行误差与失败处理预算，并与退出方案比较。系统 gate 通过不是盈利证明。
- **未知状态**：禁止重发展期、猜测成交量或盲目反向修复；先核查交易和仓位。必要时只按预定应急方案处理已独立确认的仓位。
- **缺项不启动**：资金、成交语义、风险预算、退出渠道、截止时间或验收证据不完整，保持“未就绪”。到期前仍未就绪，进入已验证的缩仓/退出方案。

制定本计划不代表退出方案已验证；展期与退出均须具备真实可用的执行渠道和预算。若到期前无法完成核验，立即转入人工风险处置与值守，不宣称已能安全退出。

## 2. 执行前核验与台账

| 项目 | 必须填写或取得的证据 |
|---|---|
| 旧仓 | 两条腿的平台、标的、market ID、方向、原生数量、ETH 等效敞口、到期时间 |
| 时间 | Unix 时间、UTC/北京时间；旧两腿失效边界、最后可交易时间、最终结算与资金释放条件 |
| 永续 | 精确合约、平台、方向、实际数量、合约乘数；与其他策略共用持仓时的归属证据 |
| 新仓 | 两条 market ID、共同到期日、资金费来源、实际生效区间；同标的/平台/方向及正确抵押品 |
| 账户 | Boros/Gate 各自权益、IM、MM、可用余额、已有负债、结算消耗、gas 和授权 |
| 成交 | 本批旧仓退出与新仓建立的真实报价、最薄盘口、费用、滑点和实际规模模拟 |
| 预算 | 常规执行成本、失败处理成本、资金费缺口/过覆盖预算、紧急价格净敞口预算 |
| 渠道 | 专用展期、状态查询、撤单/减仓、备用渠道；值守人与风险交接人 |
| 截止 | 展期最迟启动时刻、转退出的决策时刻、退出最迟启动时刻及失败恢复余量 |

数量先按合约与 Boros 原生单位换算成同一标的敞口，不能把美元名义本金当成 ETH 数量。每个平台分别匹配其资金费来源、方向和数量；两条永续净 ETH 为零不能替代逐腿资金费匹配。

旧仓两腿到期不同、下一期方向反转、更换平台/标的，均不按正常继承处理；另审期限错配修复或退出重建。新到期更晚也不意味着浮动资金费只在旧仓到期后开始；提前全量开新仓可能形成过覆盖。

台账每个 market 独立一行：`平台 | market ID | 到期 | 方向 | 原生数量 | 等效敞口 | 是否仍有效 | 对应永续 | 订单/交易 ID | 采集时间`。保留每批操作前后快照，不能仅保存账户合计值。

## 3. 复用现有专用展期能力

本地已有专用展期 UI（`RollReview`）及 `/boros/roll/simulate`、`/boros/roll/execute`。该执行链只操作 Boros，保留 CrossEx 永续；不要改用普通四腿开仓流程来继承永续，也不要把费用展示的展期开关当作执行按钮。

模拟与执行分别负责：

1. 模拟旧仓退出、新仓建立，并请求官方全批 preview；检查新到期更晚、抵押品、逐腿平台/标的/方向和规模。
2. 返回 `availableBefore`、`availableAfterExit`、`availableAfter`、`marginRequired`、`shortfall` 等阶段数据。
3. 执行前重新报价和计算 gate，拒绝 blockers；从官方展期构建器取得 calldata，以单次批处理提交，多调用设置 `requireSuccess`。

上述是本地实现事实，源码出处见审核记录。全量成交/FOK 语义依赖官方构建器，当前尚未独立核验；必须取得可追溯的当前官方保证或充分的实现与链上证据，确认全额成交、回滚及资金费生效边界，再允许实际展期。预检成功或 UI 文案不足以替代该核验。

## 4. 展期准入、现金与收益

| 准入项 | 执行标准 |
|---|---|
| 身份与期限 | 旧新仓及永续逐腿匹配；新两腿同到期且更晚；实际操作允许，官方成交语义已核验 |
| 订单与数据 | 无未查明交易、挂单、部分成交或 halted 任务；持仓与账户预检建议不超过 120 秒，下单前即时刷新报价 |
| 深度 | `rollover.depth_coverage_ratio >= 1`，且每腿实际允许滑点内覆盖本批；旧仓退出深度也要核验 |
| Boros | 每个相关账户 IM 覆盖率不低于 1.3、MM 健康度不低于 1.5；可用 ETH 留足结算/执行缓冲，不贴着 0.005 ETH 运行 |
| Gate | IM 覆盖率不低于 1.2、MM 健康度不低于 2；已有借款、清算距离和资金费压力另查 |
| 阶段资金 | 模拟无 shortfall，gas 与保守压力缓冲足够；各账户实有资金支持本批，无新增资金/借款依赖 |
| 收益 | 扣除实际成本后的收益满足下述风险预算要求，且比较退出方案后值得持有 |
| 应急准备 | 缺口、过覆盖、价格净敞口及损失上限已填写；退出渠道和双腿失败处理已验证；截止时间明确 |

保证金线沿用清单的 WARNING 边界，应留额外余量；它们不是平台清算线，也不是安全保证。`rollover.post_roll_coverage >= 1.3` 须有真实模拟证据并说明账户/分母，不能代替上表逐账户检查。

### 不追加资金的可行规模

从目标规模开始模拟；不满足资金、深度或风险条件就缩小本批及总展期规模，并重新模拟。没有可行规模则退出，不通过调低安全线凑出可行规模。

批处理预算使用真实的“退出前—退出后—新仓建立后”阶段数据，不预设完整新旧仓保证金同时占用，也不把退出后余额再加一次旧仓释放金额。执行路径存在其他占用时须另计。美元汇总不能代替各账户需要的 ETH/USDT/USDC。

每个阶段分别核对：`该阶段可实际动用资金 − 尚需新增占用 − 未计入模拟的 gas/费用 − 结算与价格压力缓冲 >= 0`。已扣除的占用或费用不得重复扣；账户资金释放也不得重复加。

IM、MM 覆盖及负债另行检查，不能仅用此差值验收。需要跨账户调拨时必须事先明确额度、时延并确认到账，且不抽走另一账户必要缓冲；未验证调拨通道或需增加资金才可行时，该规模不通过。

### 从现在开始比较经济性

共同观察终点取下一期到期，分别列出提前展期、继续持有旧仓后退出、立即退出的现金流、资金占用与风险；不同终点的年化数不能直接比较。旧期已赚收益和历史开仓成本是共同历史项，不成为强行展期的理由。

以当前账户净资产为共同起点：`预期展期净收益 = 旧仓从现在起的退出/结算增量损益 + 新仓净损益 − 尚未计入的本次及最终退出费用 − 尚未计入的已有借款利息`。本金存取、保证金释放不是收益；当前已计入净资产的估值与历史损益不得再次计入。

再单列保守的执行误差和失败处理预算；要求净收益大于该预算，并与退出方案比较。不会把风险预算当作必然发生的费用重复扣除。旧仓持有至到期的剩余收益、提前退出成交损益、价格冲击、gas 与缩仓永续成本均须按所选路径列入。

若使用 `本金 × 固定利差 × 天数 / 年化天数` 估算新仓现金流，核实实际本金单位、生效区间、年化口径与市场结算规则；以真实模拟/现金流为准。清单的 `netFixedApr` 按名义本金，界面的资本 APR 不能混用。扫描已扣的费用不重复扣；ETH 抵押品美元汇率损益另外记录。

## 5. 时间安排与已批准路径

`T` 为旧仓最早失去对应资金费对冲的真实时点。分别记录展期和退出渠道的最后可操作时间；两条路径各自预留操作、查询确认、失败恢复和安全余量。

`展期最迟启动 = min(T, 展期最后可操作时间) − 保守展期耗时 − 失败恢复耗时 − 安全余量`

退出最迟启动按退出自身约束同样倒推。**转退出的决策时刻不得晚于退出最迟启动**；不能等展期窗口耗尽后才发现退出窗口也已耗尽。耗时、余量或任一截止时间无法确定时，不启动展期。

| 阶段 | 完成标准 |
|---|---|
| 现在 | 填台账、核验平台规则/渠道，取得账户与报价，确认不追加资金的可行规模 |
| 截止前的准备窗口 | 完成批处理模拟、经济性与压力预算；指定值守者，验证退出与查询路径 |
| 决策时刻之前 | 所有准入项通过才选展期，否则选部分展期/退出；压缩日程不能省掉核验 |
| 每个执行批次 | 即时重模拟、提交一次、查状态、逐 market 对账、复核缓冲，再决定下一批 |
| T 前后 | 核对剩余旧仓、新仓生效和永续匹配；值守到交易状态及残量查明 |
| 切换后 1h / 24h | 复查保证金、负债、结算和监控，完成费用归档与结算尾项 |

### 路径 A：到期前专用批处理展期

1. 选取在旧两腿仍可关闭的窗口；两条永续保持不变，取得本批四条 Boros 腿的即时模拟与真实报价。
2. 本批不超过最薄盘口、可用资金和风险预算；首次只用满足最小交易单位、能取得有效成交/核查证据的规模，不固定采用总仓位的 5%–10%。试批也是实际交易，所有准入项仍须通过。
3. 保存模拟参数、四个 market、预计数量、报价/gate 与时间；执行入口会再模拟，若出现 blocker 或超预算则停止本批。
4. 仅提交一次专用批处理，保存响应、订单/交易标识；进入第 6 节的状态分支。不因接口超时提交第二笔。
5. 成功确认后逐平台对账：有效旧仓加新仓的等效敞口匹配对应永续；旧剩余两腿相互匹配、新增两腿同期限且相互匹配。
6. 每批重算剩余规模、经济性、保证金及剩余时间；全部通过才继续。到决策截止仍不能完成的剩余规模转退出。

示例：每条永续为 10 ETH，一批原子展期 1 ETH 经确认后，每个平台应为旧期 9、新期 1、永续 10 ETH。旧期 10、新期 1、永续 10 则过覆盖 1 ETH。示例只说明验收关系，不规定交易规模。

### 路径 B：部分展期或退出

- 若只有 `q` 可行，只展期 `q`；`Q−q` 在仍可操作的窗口内协调关闭旧 Boros 与对应永续，不把无资金费覆盖的永续留至到期后。
- 完全不展期时使用已经验证的退出方案；旧仓已失效则不假设 `/boros/roll/execute` 仍适用，核查结算与剩余两条永续并按应急退出方案处理。
- 退出前逐批保存已确认仓位和订单状态，明确各腿顺序、减仓数量及 reduce-only 支持；一腿失败时先查成交量，再处理已确认的价格/资金费残量，禁止盲目等量重试。
- 正常退出仍以保持中性为目标；紧急减仓无法同时成交时，只在事先批准的数量、时间和损失上限内承担净敞口，并持续修复残量。
- 市场受限时核实仍允许的减仓/结算操作；无法完成匹配或退出，明确记录风险、保证金缓冲与值守交接，不能标记完成。

## 6. 状态、风险预算与应急动作

常规展期不主动制造逐腿缺口；预先分别填写资金费少覆盖、过覆盖与紧急永续价格净敞口的数量、时间、美元损失上限，以及本次累计成本上限。任一预算缺失均不启动。价格净敞口不包括抵押品价格风险，后者另查。

不把默认 300 秒缺口告警当作可承受时间，不保留未经验证的 120 秒管理停止线。查询/确认时间预算取实际渠道证据；资金费成本要考虑离散结算边界，跨过结算时点时不能简单按秒均摊。费用、滑点、gas、回滚代价和紧急减仓成本都须纳入失败预算。

| 真实状态 | 必须采取的动作 |
|---|---|
| `rolled` 且证据完整 | 核对四 market 的实际净变化及继承永续；对账和保证金通过才能下一批 |
| `refused` | 核对未形成未知已提交交易、持仓未变；查明原因，修正后重新模拟，不机械重试 |
| 已证实链上回滚 | 核对回滚终态、仓位未变及实际 gas；有时间/预算才重新模拟，否则转退出 |
| `unknown`、哈希/状态缺失或结果矛盾 | 停止新增及重发；查 `/tx-status-with-events`、receipt/events 与四 market 持仓；`rolledSize=0` 不证明实际未成交 |
| 实际非预期净变化 | 视为异常事件而非正常补齐流程；查交易和订单，按已批准应急方案修复独立确认的残量 |
| 报价、收益、资金或截止越界 | 停止后续批次，处理当前已确认仓位与未决交易，再转已验证的缩仓/退出方案 |
| API/终端失效 | 用已验证备用查询渠道确认状态；状态不能核实时不扩仓，并持续值守、恢复取证 |

交易 unknown 不等于冻结所有风险处置：临近截止或保证金危险时，可根据独立确认的仓位和现有订单，在预定应急预算内减仓。不得猜测未知成交、不盲目反向修复，也不能把现有 Boros/永续重新配对视为理所当然。行动前评估对价格敞口和资金费敞口的共同影响，记录行动后的残量；无法取得可靠仓位或没有预算则不伪称可执行。

“停止”指停止新增批次；已提交交易和残量仍由值守者跟进到查明、匹配或明确交接。不能因达到展期成本线便放任清算风险，也不将紧急例外解释成无限损失授权。

## 7. 独立验收与结算尾项

风险监控默认每 300 秒运行，不代替交易跟踪。当前 `risk_monitor.py` 对同 venue 多个 Boros 仓只保留其中一条作期限判断，可能误报或漏报；新 market ID 也会与旧基线发生差异。旧新共存必须逐平台、逐 market 人工对账，不能以期限指标正常证明全量匹配，也不能关闭告警掩盖残量。

ETH 抵押品价格风险和实际退出成本有停用检查，展期时人工补查。重叠/增量保证金等外部证据须有真实模拟、来源及时间；契约 TTL 上限不能替代执行前刷新。不可用指标保持 UNKNOWN。

**切换完成**须同时满足：

1. 目标旧仓无有效残量，无未查明交易/挂单；新两腿 market、方向、规模及到期正确。
2. 逐平台资金费敞口匹配永续；价格净敞口、资金费尾差符合批准上限与合约交易单位，无法修复部分单独记录并处理。
3. 每个相关账户 IM、MM、可用资金、已有借款和压力缓冲通过，授权、gas、查询及值守可用。
4. 四 market 成交/交易证据与台账一致；仍未查明的状态不得用更新监控基线“消除”。

旧仓最终结算和资金释放未完成时只标记“切换完成，结算待验收”。最终结算完成须核实相关现金流与余额，不以到期倒计时归零代替。

完整对账后再按清单流程人工 `--accept-baseline`，更新必要配置并检查下一轮报告；不要让基线跟随异常减仓。实际保留的永续部分才在旧期采用 `Omit (rolling over)`、新期省略历史开仓费；数量调整仍计费，未来最终退出成本始终保留。

旧仓退出/结算、新仓建立、gas、已有借款利息、永续缩仓及 ETH 汇率损益分项记账，避免历史费重复归到新期。切换后 1 小时及 24 小时复查；结算消耗按最近 24 小时逐笔净事件汇总，须完整读取分页，首次运行无需等待本地采样。事件读取或校验不完整时结算消耗为 UNKNOWN；runway 还须取得同一抵押池的官方可用余额，不依赖美元报价或正 IM。
