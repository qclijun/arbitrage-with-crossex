# Boros Maker 实现方式与代价

讨论日期：2026-10-10。本文记录设计讨论，尚未实施。

**Boros Maker 可以实现，但省下的交易费，要与等待、补腿滑点和额外 Gas 一起算。建议第一版先做“一条 Boros Maker，另一条按实际成交量 Taker 补齐”。**

本文先按新开套利仓位讨论；移仓还涉及旧仓退出，需要另行设计。

## 能省哪些费用？

真正挂在订单簿上、被别人吃掉的 Maker 成交不收 Boros 交易费。但结算费仍然收取，首次进入市场的入场费也不因 Maker 而免除。挂单、撤单等操作还需要计算 Gas 成本。[官方费用说明](https://docs.pendle.finance/boros-docs/boros-systems/fees)

沿用此前核查的那笔开仓及当时美元估值：两条 Boros 腿交易费合计约 **$2.06**。在数量、剩余期限和费率相同的条件下，一条改为 Maker，大约省 **$1.03**；两条都 Maker，大约省 **$2.06**。这是历史案例的比较基准。

| 方案 | 费用收益 | 主要代价 |
|---|---|---|
| 一条 Maker，另一条 Taker | 省一条腿交易费 | Maker 成交后，另一腿价格可能已变 |
| 两条都 Maker | 两条交易费均可省 | 成交时间、数量不一致，可能长期缺腿 |
| Maker 等待，超时转 Taker | 部分成交可能省费 | 多出挂撤单成本，最终仍可能付 Taker 费 |

## 终端需要怎样实现？

讨论时的 Boros 下单明确使用 IOC：立即成交，剩余数量取消，见 `src/core/boros/borosApi.ts` 的下单请求构造。现有双腿提交会统计成交量差，见 `src/core/boros/orders.ts` 的 `submitBorosPair`。

Maker 应使用 **ALO，也就是 Post-only**。普通 GTC 可能立即吃单，产生 Taker 费；ALO 会在订单能够立即成交时拒绝交易，保证挂单身份。[官方订单类型](https://docs.pendle.finance/boros-dev/Contracts/CustomTypes)

但不能只把 `IOC` 改成 `ALO`。需要把挂单的整个生命周期纳入现有持久化交易引擎：

1. **先检查补腿条件。** 用另一条腿真实可成交的深度和 APR，倒推 Maker 挂单价格、数量，保证扣费后的收益达到门槛。
2. **小批量挂 Maker。** 下单前持久化记录，并预留挂单全部成交所需的保证金。
3. **按确认成交的增量补腿。** Maker 成交多少，就处理对应数量；另一条 Boros IOC 若只部分成交，先解决缺口，再继续增加仓位。
4. **协调 CrossEx 两条永续腿。** 同样以确认成交数量推进，处理最小下单量和尾差；整个四腿过程仍存在完成时间差。
5. **管理撤单和恢复。** 收益不足或超时就撤单；确认撤单结果并核对撤单期间的新增成交，才允许重挂。服务重启后继续管理原订单，结果未知时先查询，避免重复下单。

即便两条 Maker 在同一笔交易里一起挂出，**后续成交也不会自动同步**。

## 最关键的代价是 APR，而不只是 Gas

设匹配后的名义本金为 `N`、剩余期限为 `T` 年、被省掉的交易费率为 `f`：

```text
省下的交易费 = N × f × T
```

如果等待导致另一腿成交 APR 恶化了 `Δr`：

```text
损失的锁定收益 ≈ N × Δr × T
```

因此，假设该市场交易费率是年化 **0.05%，即 5 bp**，另一腿 APR 恶化 **5 bp**，就大约抵消了这一腿的全部手续费节省；额外 Gas 还没算进去。具体费率必须按市场读取。[费用计算公式](https://docs.pendle.finance/boros-docs/boros-systems/fees)

此外还有几个实际成本：

- **排队与错失机会。** Boros 按利率、时间排序，同价位先挂先成交；频繁撤单重挂会失去原有位置。[撮合规则](https://docs.pendle.finance/boros-dev/Mechanics/OrderBook)
- **不利选择。** 别人愿意吃你的挂单时，另一条腿的行情可能已经向不利方向移动。
- **缺腿与保证金占用。** 挂单可能零成交，也可能突然全部成交；不能假设届时补腿深度仍在。
- **离线风险。** 终端停止运行后，链上的挂单仍可能成交，补腿程序却无法及时响应。

## 第一版建议与待确定策略

第一版应采用：**单条 Maker、小批量成交、严格限制未补齐数量、有限等待和重挂次数，并按最终四腿收益验收。**

最重要的策略选择是：**Maker 已成交，而补腿价格跌破收益门槛时，愿意牺牲多少利润来消除敞口？** 这个损失上限比“挂多久”更应先确定。
