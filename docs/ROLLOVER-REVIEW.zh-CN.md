# 展期计划审核与决策记录

初审日期：2026-10-04；决策确认与计划修订日期：2026-10-05。对象：[展期计划](ROLLOVER-PLAN.zh-CN.md)。状态：策略决策已达成共识并合并入计划；执行就绪尚未通过。本记录不授权交易。

## 已确认的决策

- Q1：优先降低失配与清算风险，允许部分展期或全部退出。维持规模和节省手续费不能优先于风险控制。
- Q2：最终确认不追加资金，ETH/USDT/USDC 新增预算均为零；不新增借款。此前允许追加自有资金的选项已被本决定替代。
- Q3：常规展期保持永续价格中性；紧急减仓允许受限净敞口，其数量、时间和美元损失上限待确定。
- Q4：接受推荐，以经核验的专用批处理为默认；不可用时暂停新增、准备缩仓或退出，人工分步替换须另审完整方案。
- Q5：接受推荐，净收益扣除实际成本后须覆盖执行误差与失败处理预算，并与退出方案比较；执行 gate 通过不代替收益决策。
- Q6：接受推荐，unknown 时禁止重发展期，先查交易和实际仓位；临近截止或保证金危险时，只按预定应急预算处理独立确认的仓位。
- Q7：接受推荐，资金、风险预算、官方成交语义、退出渠道或截止时间未确定时禁止启动；到期前仍未就绪，进入已验证的缩仓/退出方案。

## 初版审核发现

本节保留 2026-10-04 初审证据；其中计划行号指初版，不对应修订后的行号。代码证据是当日核查结果，执行前仍须确认本机配置及接口可用。

### F1：主路径遗漏现有 Boros 专用批处理展期能力（阻断）

计划第 82–93 行将逐腿分批替换作为优先路径，第 88 行仍让操作者临场决定执行顺序。项目实际已有 `/boros/roll/simulate` 与 `/boros/roll/execute`，执行时重新模拟并检查 gate，再调用仅针对 Boros 的展期构建器；不触发 CrossEx 永续下单。

依据：`src/server/routes/borosPair.ts:968–1049`、`src/core/boros/borosApi.ts:643–667`。应先评估复用该路径，再决定人工分步替换是否需要作为备用；不能把现有能力留在 UNKNOWN。

原子性仍有边界：`borosApi.ts:416–424` 对多调用设置 `requireSuccess`；四条腿 calldata 来自官方 `/agent/roll-over` 构建器（第 601–618 行）。项目未自行解码并证明 FOK 成交语义；尚未核验当前官方接口保证或实际链上成交。因此不能把 UI 的“FOK/atomic”文案当成已独立证明的全量成交保证。

### F2：失败状态需要区分拒绝与未确认（阻断）

计划第 128 行允许“补齐、回退或减仓”，但没有规定谁在什么条件下选择哪一种。已有执行实现对缺少哈希、缺少状态或子调用状态不全保留 `unknown`；`rolledSize = 0` 在未知态不证明实际仓位为零。

依据：`src/core/boros/borosApi.ts:730–760`、`src/core/boros/rollover.ts:398–410`。已拒绝、交易回滚、状态未知和已成交必须分别建处理分支；未知态先查交易状态、receipt/events 与四个 market 的真实仓位，不能重发或凭推测反向修复。

### F3：保证金预算未区分批处理阶段与人工重叠（重要）

计划反复强调新旧仓重叠资金需求，但已有展期模拟返回 `availableBefore`、`availableAfterExit`、`availableAfter`、`marginRequired` 和 `shortfall`，按退出旧仓后的阶段判断新仓保证金。

依据：`src/core/boros/rollover.ts:231–312`。应复用真实阶段模拟；人工先开新仓的重叠预算与同批先退出再进入的资金需求不能混用。模拟通过也不能替代 MM、结算压力、gas 和 Gate 缓冲检查。

### F4：现有监控不能完整验收旧新到期共存（重要）

计划第 139 行只要求人工解释期限告警，未明确监控会遗漏部分仓位。`scripts/risk_monitor.py:270–276` 按 venue 构造字典，同 venue 多仓只保留最后一条，然后比较被选中的两腿期限；可能误报，也可能漏掉未被选中仓位的错配。

新 market ID 与旧基线的差异还会触发非预期变动，见该文件第 306–309、366–368 行。分批切换必须使用独立的逐平台、逐 market 台账；不能以该指标正常作为完整验收证据，也不能在半成品状态接纳新基线。

### F5：120 秒停止线及试批比例缺少依据（重要）

计划第 87、105 行建议 5%–10% 试批、120 秒停止线，但没有执行耗时分布、离散资金费结算边界或美元损失上限支撑。应按真实接口能力、最薄盘口、查询/确认耗时与用户风险预算确定；300 秒告警阈值不能换算成可承受风险。

### F6：系统 gate 通过不代表展期值得做（重要）

现有 gate 验证更晚到期、同抵押品、逐腿身份/方向/规模与执行条件，见 `src/core/boros/rollover.ts:187–225`；执行端会再次模拟并拒绝 blockers，见 `src/server/routes/borosPair.ts:1020`。下一期美元净利润和用户收益底线并非该 gate 的完整硬条件。

需要独立比较从现在开始的提前切换、持有至到期后交接和退出现金流，明确交易成本、旧仓剩余收益、最终退出成本及压力预算，再作决策。

## 决策闭环与剩余执行核验

Q1–Q7 的策略决策均已确认；不追加资金、风险优先、常规价格中性已固定。具体规模、数值风险预算和截止时间保留为执行前必填项，未填写时不得启动。这不是允许操作者临场补任意值。

六项发现已按以下方式合并入计划：

1. F1：默认专用批处理；官方全量成交语义尚未核验，列为启动禁止条件；人工分步和到期后单独开新仓另审。
2. F2：分别处理 rolled/refused/unknown 与已证实回滚；未知禁止重发，只允许有可靠仓位证据和预算的应急处置。
3. F3：复用真实阶段模拟，不预设完整重叠保证金；按不追加资金约束缩小可行规模。
4. F4：明确监控多期限盲区，独立逐 market 台账验收；完整核对后才接纳基线。
5. F5：取消固定试批比例和未经验证的 120 秒管理停止线；数量、时间与损失预算必须有依据并事先批准。
6. F6：收益与执行 gate 分开；从当前净资产出发比较增量损益、最终退出费用及风险预算，保证金释放不算收益。

剩余执行核验：实时账户与规模模拟、官方成交语义、风险预算数值、展期/退出各自截止时间、退出步骤与失败动作、渠道及值守。这些尚未验证；因此只完成策略审核与文档修订，不标记展期或退出已就绪。

术语见 [GLOSSARY.md](../GLOSSARY.md)。该策略可调整，未产生需要 ADR 的难以逆转架构决策，不创建 ADR。原执行计划已按确认决策统一修订。
