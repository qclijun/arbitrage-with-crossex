# 引擎分段观测 RSS 门禁复测

日期：2026-10-23。补充 [2026-10-16 离线验收](engine-observation-2026-10-16.md)中未通过的
正常 GC 稳态 RSS 门禁。原报告及其 FAIL 记录保持不变。运行环境：Node 24.21.0。

**结论：用户接受本次固定 V8 新生代后的复测作为 06 的 RSS 门禁证据，06 验收通过。**
生产启动参数不变。证据 JSON 见 [engine-observation-rss-2026-10-23.json](engine-observation-rss-2026-10-23.json)。

## 原失败的原因

原版和观测版都出现约 140 MiB 的 RSS 台阶，无观测的 Store 读取也能复现。
以下离线对照说明台阶来自 V8 动态扩大新生代后保留的高水位，不来自观测器或 SQLite：

| 实验（32000 轮，每轮 121 次读 pair + 1 次读 121 个订单） | RSS 起 → 峰 MiB | 堆峰值 MiB |
|---|---:|---:|
| `tests/bench/engine-store-read-memory.cjs`，默认参数 | 118.8 → 330.4 | 52.3 |
| 同上，`NODE_OPTIONS=--max-semi-space-size=1` | 102.6 → 108.9 | 17.7 |
| 临时脚本：同形状 node:sqlite 读取，每次 `prepare` | 42.6 → 224.7 | 35.8 |
| 临时脚本：同上但复用语句 | 42.7 → 180.9 | 37.2 |
| 临时脚本：同形状纯 JS 分配，不用 SQLite | 40.6 → 188.0 | 64.4 |
| 临时脚本：每次 `prepare`，固定新生代 1 MiB | 后段稳定在 72.8 | 未完整记录 |

纯 JS 也会出现同样的台阶；固定新生代后台阶消失。每次 `prepare` 只多出几十 MiB，
不是主因。临时脚本未入库，以上数字只作诊断。

台阶出现在随机时点，两个配置很难在同一检查点同时稳定，所以原门禁判"无共同稳定点"。
它测到的是 V8 新生代的伸缩，不是观测器的增量。

## 复测方法

在临时 worktree 检出 06 的提交 `1271d2d`（纯观测版，不含 09 的优化），对照原版
`1fe452cfe04c3ee44c18dca5c19e3df2f1a8e970`。基准脚本与 06 当时相同
（SHA-256 `bf43ebd4…`），门禁、检查点和阈值不变。唯一变化是两组子进程都继承
`NODE_OPTIONS=--max-semi-space-size=1`：

```sh
NODE_OPTIONS=--max-semi-space-size=1 node --import tsx tests/bench/engine-observation.ts 1fe452cfe04c3ee44c18dca5c19e3df2f1a8e970
```

## 结果

| 组 | 原 p95 ms | 观测 p95 ms | 开销 ms | 共同稳定检查点 | 稳态 RSS 增量 MiB | 账本一致 |
|---|---:|---:|---:|---|---:|---|
| 1 | 2.8225 | 3.0379 | +0.2154 | 120 | 24.95 | 是 |
| 2 | 3.0555 | 3.2443 | +0.1889 | 80 | 25.11 | 是 |
| 3 | 3.2134 | 3.5058 | +0.2924 | 120 | 11.71 | 是 |

合并 3000 ticks：原 p95 3.0208 ms，观测 3.3100 ms，开销 +0.2892 ms，预算 1 ms。
三组所选检查点之后的预定检查点都保持稳定，没有触发后续增长否决；每组 121 次创建，整体 `pass: true`。

## 局限

- 生产使用 Node 默认参数。默认参数下两个配置都会出现 V8 新生代高水位；
  本次没有直接测出默认参数下观测器的增量。
- 仍是有限次合成离线样本，不证明实盘延迟、未对冲暴露或未来运行不增长。
- 本次没有部署、重启、启用观测、访问真实账户或交易。
