# 02: 让HL重点合约在预算内持续更新，并显示过期原因

Type: task
Status: ready-for-agent
Blocked by: None (can start immediately)

**What to build:** BTC和ETH的近期历史优先更新到共同截止点，长历史回填能继续推进。用户可在已有单场所历史页面看见因预算、超时或限流而等待的具体窗口，避免一个合约的全年回填长期挤掉另一个合约。本票可独立演示，不依赖新增配对。

- [ ] 使用现有请求、权重、超时及限流预算；保证重点BTC/ETH近期窗口的公平调度，长窗口回填不会使另一个重点合约反复停留在旧截止点。
- [ ] 中断的历史回填能在后续轮次取得实际进展；在容量足够、源恢复且无异常的固定样本中，后续轮次最终完成两合约的五窗口，而不是重复消耗预算后持续停在同一缺口。
- [ ] 已完成的短窗口不因长窗口失败而失去独立覆盖结果。旧长窗口保留原截止点和核验时间，不能拼接不同截止点的两腿，不能把失败重试标成新鲜数据。
- [ ] 历史读接口和页面清楚显示各合约/窗口的截止点、新鲜度、最近尝试及预算耗尽/超时/限流原因；资料恢复后自动刷新相应状态，页面请求只读缓存。
- [ ] 在确定性的预算耗尽、超时、限流及恢复场景下验证上述行为；新旧记录冲突仍被保留，不增加外部请求上限；项目离线检查和生产构建通过。
