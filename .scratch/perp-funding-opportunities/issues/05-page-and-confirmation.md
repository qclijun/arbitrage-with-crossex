# 页面、详情与确认交互原型

Type: prototype
Status: resolved
Assignee: Codex
Blocked by: 02, 03, 04

## Question

既定数据/执行/归属契约下，如何用升级后的Funding Spreads独立页，让用户看懂历史浮动收益、支持/不支持原因，并完成一次真实规模的人工两腿开仓确认？

本票需与用户看可交互/具体原型再定案；不能由代理代替用户验收。原型是讨论资产，不是偷偷上线的产品实现。保留四腿/三腿入口。

### 原型必须覆盖

默认30天排名＋7天对照、五窗口切换、当前一期另列；多venue组合、方向、币种/交易所筛选；UNKNOWN/部分失败/过期/假设费率；非白名单/跨单位只观察；编辑规模杠杆后重报价、确认、执行进度与残余；持仓归属和风险反馈入口。

### 输入

[组合与成本](02-pairs-costs-and-ranking.md)、[执行边界](03-preflight-and-execution.md)、[归属与风险](04-ownership-and-risk.md)。

## Answer

采用[A排名工作台](../page-prototype.md)：左侧密集有向组合排名表、右侧连续详情；历史证据、规模/成本、人工预览确认、执行进度/残余及归属/Risk反馈按已展示交互验收。默认30天＋7天对照，保留五窗口、过滤/分页、零负/反向结果和具体UNKNOWN/执行阻止原因；四腿/三腿入口保留。

用户于2026-10-27明确选择A且确认交互可验收，无新增修改要求。B/C仅保留比较资产，不作为首版布局；01—04契约继续适用，原型不扩大白名单、价格保护、持久恢复或收益归因能力。原型提交7b74406及[核查记录](../evidence/prototype-review.md)提供可审阅证据；此结论仅关闭原型决策，不表示生产功能已交付。下一张决策票为[06规格验收与交付准入](06-acceptance-and-rollout.md)，整体规格仍draft，实施票仍须等待06。
