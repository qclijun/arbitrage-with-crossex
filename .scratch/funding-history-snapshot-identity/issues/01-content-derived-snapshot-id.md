# 01: 快照 id 由内容决定，去掉 'unchanged' 分支

**What to build:** 历史快照的 id 由截止点和每条腿参与评估的证据决定，不再按轮次生成。后台刷新器每轮都照常发布快照；只要排名和开仓准入用到的证据没变，id 就不变。用户在 Funding 页面上看到的效果：没有新结算的轮次里，已经拿到的 Preview 仍可接受，订单表单不会退回草稿，翻页时也不会误报“排名已变”并跳回第 1 页。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

背景：现在的 id 是 `fh-<cutoff>-<startedAt>-<seq>`，每次发布都换新。新 id 会让服务端开仓复核以 `history-snapshot-superseded` 拒绝旧 Preview，让前端订单表单丢掉已有 Preview，并让分页排名指纹变化。上一次改动（commit `7e644cb`）加了 `'unchanged'` 分支：一个腿都没尝试的轮次不发布，以保持 id 不变。但这只覆盖了一种情况。只读到 Hyperliquid 回填页、或只记了一次失败尝试的轮次，排名证据没变，id 照样会换。这个分支是在绕开“准入绑定轮次而非证据”的问题，本工单从根上解决它（2026-11-01 code review 第 9 条）。

## 计入 id 的内容

- **计入**：快照截止点；每条腿用于评估的读取（读取截止点、结算记录、规则分段、上市信息、来源状态、覆盖区间与完整性）；沿用证明（from、next）；是否为重启恢复的数据。
- **不计入**：尝试时间与结果、失败原因、核验和观察时间戳、Hyperliquid 回填进度与已读页数。这些只用于展示，照常随快照发布，页面上仍能看到。

实现时要先核对评估实际读取了哪些字段，确保计入的内容是它们的超集。宁可多算导致 id 多变，也不能漏算导致证据变了 id 却不变。

## Acceptance

- [ ] 证据相同的两轮发布出的快照 id 相同；结算记录、规则、覆盖区间、沿用证明、恢复标记或截止点中任何一项变化，id 都会变
- [ ] 只读到 Hyperliquid 回填页、但没改变任何窗口证据的轮次，id 不变；回填补齐长窗口、改变了某个窗口证据的轮次，id 会变
- [ ] 失败尝试照常发布，页面能看到失败提示和最新尝试时间，但 id 不变
- [ ] 重启恢复的快照，id 与本进程读到的同内容快照不同，恢复的数据仍不能通过准入
- [ ] 删除 `'unchanged'` 分支和这个 outcome（含页面文案与测试）
- [ ] 服务端测试：Preview 之后发布一轮证据未变的快照，接受仍成功；证据变化后接受被拒
- [ ] 前端测试：快照 id 不变的重新拉取，不清空订单表单里已有的 Preview
- [ ] 未变的腿不重复计算摘要，每轮开销与有变化的腿数成正比
- [ ] `yarn verify`（必要时清空 `GATE_PROXY`）和 `yarn --cwd web build` 通过；不重启线上服务，不发真实交易请求
