# 02: 保证历史不完整与手动日期下的统计边界

**What to build:** Positions 在成交历史不足或持仓周期归属无法确认时明确展示统计不完整，不将漏读费用显示为已确认的零或完整成本；用户指定的总起点和 legSince 严格控制统计范围，同一市场平仓重开不会被误认为同一周期。

**Blocked by:** 01: 修复 Positions 默认起点与漏计费用。

**Status:** ready-for-agent

**Type:** task

**Progress:** resolved

- [x] 在工单 01 的修正路径上覆盖历史查询失败、分页截断及成交链不足等无法证明归属的情形；默认起点及费用完整性不被错误标为已确认。
- [x] API 与 Positions 界面一致传递和展示统计不完整信息；无法确认的费用不默认视为免费，无法确认的周期不混入默认统计并声称完整。
- [x] 同市场平仓后重新开仓的离线案例能区分已结束周期与可确认的当前周期，不把旧周期费用归入当前周期。
- [x] 保留用户显式总起点：早于该日期的成交费用、交易 PnL 和结算不因自动修正默认起点而被计入期间合计。
- [x] 保留 legSince 对指定市场的边界，并与总起点共同生效；不把一个市场的边界应用到其他市场。
- [x] 用户清除手动日期后回到工单 01 的账户组合默认起点；历史恢复完整后，统计不完整提示及费用数字能随重新查询正确恢复。
- [x] 使用脱敏离线 API 与必要的 UI 回归测试验证平仓重开、历史不完整及日期边界；运行相关离线测试与类型检查，不操作真实订单。
- [x] 本次不新增生命周期费用展示，不新增策略轮次管理系统，不扩展 Trades 页面。

## Answer

默认窗口按确认的成交对象集合归属当前周期，排除同秒旧仓平仓手续费。缺失费用或前后仓位字段、查询失败及分页截断均标为不完整；费用弹窗显示 UNKNOWN，相关净利润不输出已确认数字。手动总起点和 legSince 保持严格边界，完整历史恢复后提示及费用恢复。
