# 01: 修复 Positions 默认起点与漏计费用

**What to build:** Positions 默认统计能够覆盖成交历史中可确认的当前持仓周期，即使 Boros 先于永续成交，也完整计入其开仓手续费，并同步修正费用弹窗和收益数字。旧安装自动兼容修正错误默认起点，不需要用户清空历史；修正结果按 Gate 账户与 Boros 钱包组合隔离。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [ ] 默认起点根据可确认的当前持仓周期修正，不固定向前减去某个秒数，不直接采用全部 Boros 历史的最早事件，也不新增策略轮次管理系统。
- [ ] 用合成离线案例复现 Boros 两腿在 T 成交、永续在 T+25 秒开仓的漏计；修复后两腿各计入 0.0004 ETH，共 0.0008 ETH。
- [ ] 对新安装和已保存错误默认起点的旧安装均有效；已有持久化记录兼容，无需手动删除或修改。
- [ ] 按 Gate 账户与 Boros 钱包组合隔离默认起点；切换任一账户后不会沿用其他组合的修正日期，切回后仍保持正确。
- [ ] Positions 的 Boros Trade Fees、依赖该费用的净收益及预计到期利润使用一致的修正结果；说明数字变化来自补计历史费用。
- [ ] 刷新、重启和重复读取不会重复计费，也不会不断改变已确认起点。
- [ ] 保持用户显式总起点及 legSince 生效，不自动扩大手动窗口；不将未经确认归属的历史宣称为完整。
- [ ] 与现有成交链、四腿配对和账户历史语义兼容，不把配对分组当成策略轮次 ID；本次不修改 Trades 页面及交易执行行为。
- [ ] 相关离线回归测试及类型检查通过；费用弹窗和收益数字有必要的 UI 验证，验证不操作真实订单。
