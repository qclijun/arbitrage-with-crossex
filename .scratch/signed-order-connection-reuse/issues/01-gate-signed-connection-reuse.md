# 01: 优化 Gate CrossEx 签名交易客户端的连接复用

**What to build:** 让终端的 Gate CrossEx 下单、撤单和订单查询复用安全的 HTTPS 代理连接，减少重复建立连接的等待；保持签名、订单确认和不确定结果的处理语义，避免网络优化引入重复订单或延迟对冲。独立实现和验证，不直接应用到正在运行的终端服务。

**Blocked by:** None (can start immediately)。公开行情总期限修复不构成本票的阻塞依赖，不能未经验证直接复制其连接池配置。

**Status:** ready-for-agent

## 背景与范围

公开行情已验证重复建立代理隧道会增加握手耗时。当前签名 Gate 客户端仍使用 Axios 的旧代理 Agent，配置的请求超时为 15 秒；尚未通过真实下单测量交易延迟，不能把行情测量值当作下单性能证据。

本票只处理 Gate CrossEx 签名交易传输，包括下单、撤单及后续订单查询。保留现有代理配置与无代理行为，不调整 Boros 交易、订单参数、交易策略、对冲规则或行情采集预算。

## Acceptance criteria

- [ ] 在独立分支实现；提供基线与修复后的可重复离线对照，通过签名 SDK 请求到本机合成 HTTPS/CONNECT 服务验证真实连接复用，而非仅检查 Agent 对象复用。
- [ ] 同目标站的连续下单、撤单和查单请求可以复用连接；明确证据表明新建连接次数减少，记录各阶段和总耗时，不用行情延迟替代交易客户端测量。
- [ ] 保留签名计算、认证头、请求参数及 TLS 证书和主机名校验；凭据切换后每个请求使用正确身份，不交叉污染客户端认证状态，不记录真实密钥或签名。
- [ ] 保留现有 15 秒请求超时配置，不新增下单自动重试，不引入使交易取价或订单请求额外排队的共享连接上限。分别验证连接等待、CONNECT/TLS、响应及并发场景，区分请求配置与调用总期限；任何总期限语义调整须另行明确决策。
- [ ] 覆盖服务端已接受订单但客户端超时、连接重置、5xx、确认查询失败及进程恢复场景：不确定提交仍保留 PENDING/UNKNOWN，冻结该组合的新下单，按现有订单标识查询与核对，不直接重发或提前认定未成交；明确拒绝及已确认接受的处理保持一致。
- [ ] 验证上游关闭空闲连接、连接失败和代理配置变化后的恢复与资源清理；不以关闭 TLS 校验、绕过已配置代理或复用旧报价换取成功率。
- [ ] 相关签名客户端、订单状态机和端到端传输回归，以及仓库规定的离线验证与生产构建通过；提供验证记录、已证明的性能改善和未验证的实际交易影响。
- [ ] 验证默认仅使用合成数据和本机服务，不执行真实下单、撤单、账户调整或自动重启终端。通过离线验证不代表实盘验证完成；合并或应用到终端前由用户审阅具体结果。
