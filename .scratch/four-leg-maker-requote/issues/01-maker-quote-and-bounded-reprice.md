# 01：实现四腿永续 Maker 报价与有限改价

## What to build

实现已确认的[规格](../spec.md)：仅在 Boros 已建仓后的四腿永续对冲流程启用买一／卖一 post-only 报价、有限自动改价和默认三十分钟 maker 等待；已确认成交部分优先市价对冲。复用现有单写者 deal 引擎及订单账本。

## Acceptance criteria

- [ ] 新策略由四腿流程显式启用，普通双腿、单腿、平仓与已有 deal 保持旧行为；首次 maker venue 选择不变，执行中不自动切换。
- [ ] BUY 挂买一、SELL 挂卖一；保持 post-only、tick 与精度限制及既有明确拒绝／未知结果处理。
- [ ] 落后至少两个 tick、距上次挂单至少十五秒时才自动改价；最多二十次，计数持久化且重试／重启不重置或重复消耗；额度耗尽保留最后 maker。
- [ ] 改价先撤单确认、核对新增成交、处理对冲，再挂未成交剩余量；无重复下单、超额 acquire 或超额 hedge。
- [ ] 默认三十分钟，可下单前调整；绝对期限从 deal 创建计时，不因改价、成交、盘口异常或重启延长。
- [ ] 盘口失败或无效时暂停新增 maker 与改价，但保留原 maker，继续观察及对冲已确认成交；复用一秒本地缓存，不宣称已验证源盘口年龄。
- [ ] 到期优先于盘口暂停，撤单确认后按原 converting 流程补齐；pending、quarantine、manual stop／convert、hedge wall、halt 等既有安全条件保持有效。
- [ ] 不增加资金费率／结算时间等待边界、资金费损失预算或双腿入场基差检查；保持原有通用账户和交易校验。
- [ ] 交易视图可解释期限、改价次数、暂停与转换阶段；历史账本兼容，策略及进度只通过既有持久化引擎执行。
- [ ] 以已有 fake venue＋可控时钟＋真实订单账本测试完整循环，覆盖撤单成交竞态、部分成交、边界、数据异常与重启；补充 API 参数及 UI 范围隔离测试。
- [ ] 仓库规定的离线验证、相关 UI 测试与生产 web 构建通过；报告离线已证明行为与尚未证明的实盘成交效果。
