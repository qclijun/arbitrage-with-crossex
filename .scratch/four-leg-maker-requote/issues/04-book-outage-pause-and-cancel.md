# 04：盘口不可用时的报价暂停与三十秒撤销

**What to build：** 本地行情不可用时，自动报价停止新增 maker 与改价；故障短暂则保留已挂的 maker（它仍可能成交，循环继续观察订单并对冲已确认成交），故障持续超过三十秒则在订单状态仍可读的前提下请求撤销 maker。有效行情恢复且未到期则继续原 deal 并重新计算报价。暂停行为只按故障持续时长分级，不依赖故障恰好落在改价周期的哪个位置。

**Blocked by：** 02（挂同侧最优价并按落后 tick 有限自动改价）

**Status：** ready-for-agent

## 背景

现有实现有两个缺口必须一并收口：退化的单边盘口目前是**合法**的盘口对象，取价函数会把它静默降级成裸同侧最优价；中间价函数则**完全没有**买卖价关系检查，交叉盘口照样返回一个价。此外，报价价取不到时会回退到 deal 留存的上一次挂单价，而该字段在每次挂单成功后都会被写成实际挂出价——所以只要成功挂过一次，回退值永远非空，「取不到盘口就暂停」这条保证在现有实现里**不可达**，会退化成用陈旧意愿价反复往盘口里塞新单。

**验收标准**

- [ ] 新写一个显式的盘口可用性判定：存在买一与卖一、两者均为正有限值、且买一小于卖一。任一条不满足即判定为不可报价；单边盘口与交叉盘口都必须判为不可报价。
- [ ] 不可报价时既不新增 maker 也不改价，并给出可解释的暂停原因。
- [ ] **报价价**取不到时一律不新增 maker，明确反证不会回退到留存挂单价重挂。这是对现有行为的显式反证，需要专门断言。
- [ ] **对冲参考价**取不到时，已确认成交不得以任何本地留存价格对冲；按现有「无法安全提交对冲」规则冻结、退避、停止继续获取敞口并告警。
- [ ] 故障不超过三十秒时保留未撤销的现有 maker；循环继续观察订单并处理已确认成交的对冲。
- [ ] 故障超过三十秒且订单状态读取正常时请求撤销 maker——撤单不依赖盘口价，只依赖订单状态读取。
- [ ] 若订单状态读取也不可用（整个交易所接口不可用），不发出撤单、不猜测、不重发，按现有未知结果、隔离与冻结规则处理；规格要求的是「盘口不可用**且**订单状态可读 → 撤销」，不是无条件的撤销。
- [ ] 暂停行为只按持续时长分级。构造「故障恰好落在改价周期内」与「故障落在两次改价之间」两种时序，断言行为一致。
- [ ] 已发起撤单后才发生盘口异常时，不试图恢复原单；确认撤单并履行已有成交的对冲义务后，等待有效报价再重挂。
- [ ] 数据恢复且未到期时继续原 deal 并重新计算报价；已到期时进入转换，不重新开启 maker 窗口；撤销后的暂停期间持续无有效行情直至到期时直接进入转换，不得在价格未知的情况下补齐。
- [ ] 该暂停不覆盖订单状态不确定、对冲失败、手动停止／转换、对冲墙等现有必须撤单的安全条件。
- [ ] 不将缺失值当成零、不把退化盘口当作可用、也不用旧价格进行新的自动报价；成功请求或本地解析时间不得被描述为「源盘口一定新鲜」。
