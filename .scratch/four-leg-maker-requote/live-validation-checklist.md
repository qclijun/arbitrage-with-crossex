期限行为，最后用交易所成交记录确认实际 Maker 成交。

勾选表示该项已有证据支持。未自然触发的场景填写「未观察到」，不能算通过；
未执行的检查填写「未验证」。

## 1. 运行版本与入口

- [ ] 已确认运行实例的服务端和前端均加载本次 feature。
- [ ] 若需切换或重启实例，已先确认没有进行中的 deal 或未结束订单。
- [ ] 使用原本计划进行的较小交易，数量满足 Boros 和两条永续腿的最小下单规则。
- [ ] 从四腿向导进入 Boros 已建立后的永续对冲步骤。
- [ ] 永续执行方式选择 `Limit + hedge`。
- [ ] 四腿票据默认选中 `30m`。
- [ ] 首次自动报价验证没有手动输入 Maker 价格。
- [ ] 若主动调整等待时间，已记录界面选值，提交后核对实际截止时间与选值一致。

普通永续双腿票据不会启用新策略。仅确认仓库已提交代码，不等于运行实例
已经加载它。

## 2. 首次报价与策略启用

- [ ] 已保存 Deal ID。
- [ ] 进度显示 `auto-following best`。
- [ ] 初始改价计数显示 `reprices 0 / 20`。
- [ ] 已记录首次报价时的盘口观测、挂单价格及时间。
- [ ] BUY 报价等于按 venue tick 和精度规则格式化后的买一；SELL 对应卖一。
- [ ] Maker 委托采用 post-only；订单记录中的 TIF 为 `POC`。
- [ ] 执行中的 A／B 获取腿与对冲腿角色没有自动交换。

比较价格时使用挂单当时的盘口观测。稍后的盘口截图不能证明当时挂错价；
本地成功获取盘口也不等于已验证交易所源盘口的时间戳。

## 3. 自动改价与撤单重挂

- [ ] 若自然出现追价条件，已记录旧挂价、格式化后的同侧最优价及合约 tick。
- [ ] 自动改价只在挂价落后至少 2 tick，且距上次 Maker 挂单至少 15 秒时启动。
- [ ] 不足 2 tick、未满 15 秒或原报价更积极时，没有仅为追随盘口而自动撤单。
- [ ] 一个自动改价周期只增加一次计数；初次挂单不消耗改价额度。
- [ ] 重试同一次撤单或观察未知结果，没有重复增加计数。
- [ ] 原 Maker 单已确认结束并核对最终累积成交，才出现替换 Maker 单。
- [ ] 撤单期间新增成交已计入对冲义务；替换数量不含已成交或已预留数量。
- [ ] 没有重复提交同一 client ID，且没有两张 Maker 单同时获取同一剩余数量。
- [ ] 改价或部分成交后，绝对截止时间没有延长，改价计数没有归零。

若自然达到 20 次上限：

- [ ] 计数不再增长，保留最后报价；额度耗尽本身没有触发 Taker 转换。

若未出现自动改价或未达到上限，对应场景填写「未观察到」。

## 4. 已确认成交与对冲

- [ ] 达到可提交数量的已确认 Maker 成交优先以 Taker 对冲，不等待整张 Maker 单成交。
- [ ] 对冲腿没有改为 Maker。
- [ ] 累积获取量不超过目标量，累积对冲量不超过已确认获取量。
- [ ] 若存在无法满足最小数量／名义金额的 dust，终态报告如实显示。
- [ ] 目标已获取且对冲完成时正常结束，没有继续等待到截止时间。

## 5. 手动固定价格与恢复自动跟随

仅在 deal 仍处于 `OPENING` 且尚有待执行数量时验证。

- [ ] 输入固定价格并点击 `Re-peg to price` 后，显示 `not auto-following — price pinned`。
- [ ] 挂价按用户输入及 venue 格式化规则执行，没有被自动报价覆盖。
- [ ] 固定期间没有自动追价。
- [ ] 点击不带价格的 `Re-peg to touch` 后，恢复 `auto-following best`。
- [ ] 恢复报价使用当前同侧最优价，仍遵守自动改价的 15 秒间隔与既有额度。
- [ ] 手动操作没有重置绝对截止时间。

按钮名称仍叫 `Re-peg to touch`，四腿 deal 实际恢复的是 `best` 策略。
若本笔已成交结束，不为验证此项额外制造交易，填写「未观察到」。

## 6. 到期转换

若首笔期限前已全部成交，本项填写「未观察到」。后续计划交易可在提交前
选择 1m 或 5m，验证其对应期限的转换；这不等于实盘等待并验证了默认 30m。

- [ ] 到期后进入 `CONVERTING`，没有开启新的 Maker 等待窗口。
- [ ] 剩余 Maker 已请求撤销；确认最终成交后，先处理已成交部分的对冲义务。
- [ ] 随后以 Taker 获取剩余 A 数量并对冲，没有重复获取或超额对冲。
- [ ] 若存在 pending、quarantine 或无法安全确定提交数量，执行没有猜测订单结果。
- [ ] 最终报告与实际成交一致，未将拒绝、未成交剩余量或 dust 隐藏为全部完成。

连续 post-only 拒绝耗尽独立预算时可能提前转换。应结合订单拒绝记录辨别
转换原因，不能把它误判为改价达到 20 次触发。

## 7. 交易所成交与费用核对

- [ ] 已保存对应交易所订单及成交明细。
- [ ] 用成交记录的 Maker／Taker 身份确认是否实际获得 Maker 成交。
- [ ] 已核对每腿实际成交量、成交价及手续费。
- [ ] Maker 成交与到期／拒绝预算转换后的 Taker 成交分别记录。
- [ ] 若评估成本，永续手续费与 Boros 交易／结算／入口费用、Gas、兑换价差分别记录。

post-only 委托记录证明下单方式；实际 Maker 成交仍需成交记录支持。
若全部通过 Taker 补齐，不能仅凭这一笔判定 feature 失败，也不能据一笔
Maker 成交宣称总体成交率或总成本已经改善。

## 8. 中止与验证边界

- [ ] 若使用 `Stop`，已核对它停止继续获取数量并处理已有成交的对冲义务。
- [ ] 已确认 `Stop` 不会自动关闭 Boros 腿或清空已成交持仓。
- [ ] 验证结束后，已核对实际持仓；后续持有或平仓按原交易计划处理。
- [ ] 没有为实盘验收人为断网、强杀进程或故意耗尽拒绝／改价预算。

故障、崩溃及难以自然触发的预算边界继续使用离线模拟验证。若实盘自然
出现盘口异常，记录暂停、撤单、恢复和期限行为，不将未观察到的边界算通过。
