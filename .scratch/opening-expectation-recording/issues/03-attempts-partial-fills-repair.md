# 03: 失败、部分成交与继续补单的操作追踪

Type: task
Status: ready-for-agent

**What to build:** 历史能够解释一次开仓从失败或部分成交到继续补单的全过程，并诚实表达记录缺失与可补写范围。

**Blocked by:** 01

实施范围：沿用规格确认的交易流程；留档不得阻止或延迟发送、对冲、补单及恢复，不改变交易准入、幂等或执行数量。采用 SQLite 系统记录和单写者约束，不新增交易调用，不记录凭证，沿用 localhost、Host/Origin 与 API token 保护。

## Acceptance criteria

- [ ] 拒绝、失败、部分成交、撤单转 taker 和补单保留操作身份，各有尝试身份，关联所有订单及成交且不重复计费。
- [ ] 同流程补单沿用操作；重新发起默认新操作，从历史明确选择继续补单才关联原操作。
- [ ] 展示目标、完成和未完成数量，不把整笔预期当作已成交部分收益；未成交或失败也能从历史查询。
- [ ] 留档重试只补记录或查询既有订单，不重发交易；unknown 探测和既有恢复保持原样。
- [ ] 有证据时标明缺失/不完整，原始快照仍在则可补写；已丢失报价保持缺失，全部证据丢失时不声称能枚举尝试。
- [ ] 故障注入覆盖发送、对冲、补单和恢复，验证留档不增加等待或无界积压，执行结果与未启用留档一致。
- [ ] 本票交付相应持久化、API、界面与离线回归验证；使用单元/API/UI 测试及假交易所，不使用实盘下单验收。
