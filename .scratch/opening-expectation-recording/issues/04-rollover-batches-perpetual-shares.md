# 04: 按批次记录展期与永续沿用份额

Type: task
Status: ready-for-agent

**What to build:** 从 Positions 持仓确认面板展期后，用户可在策略历史查看每个展期批次的面板原报价、实际条件、尝试与执行结果。

**Blocked by:** 02, 03

实施范围：沿用规格确认的交易流程；留档不得阻止或延迟发送、对冲、补单及恢复，不改变交易准入、幂等或执行数量。采用 SQLite 系统记录和单写者约束，不新增交易调用，不记录凭证，沿用 localhost、Host/Origin 与 API token 保护。

## Acceptance criteria

- [ ] 首次开仓与每次展期分别记录；标明面板报价来源、已有估算范围和条件差异，不用新市场普通开仓报价冒充整个展期预期。
- [ ] 沿用永续时仅记录已有数量份额，不制造成交或重复收取开仓费用。
- [ ] 展期部分成交、失败和补单沿用已定义的操作/尝试规则；成功持久化的数据重启及备份恢复后可查。
- [ ] 只有来源唯一明确才自动关联；共享、历史或多来源仓位保留待关联状态，不按时间或当前配对比例猜归属。
- [ ] 离线覆盖多批展期、沿用永续及异常执行，验证无新增市场操作。
- [ ] 本票交付相应持久化、API、界面与离线回归验证；使用单元/API/UI 测试及假交易所，不使用实盘下单验收。
