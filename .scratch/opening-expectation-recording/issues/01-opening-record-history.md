# 01: 正常四腿开仓的预期留档与历史查询

Type: task
Status: ready-for-agent

**What to build:** 从机会页到确认发送保留原始报价，成功开仓后可在 Positions 历史及持仓、永续交易详情查看同一操作的报价、提交条件、两条 Boros 腿和多个永续订单/成交。首次实现前明确并记录单写者调度与故障隔离方案。

**Blocked by:** None (can start immediately)

实施范围：沿用规格确认的交易流程；留档不得阻止或延迟发送、对冲、补单及恢复，不改变交易准入、幂等或执行数量。采用 SQLite 系统记录和单写者约束，不新增交易调用，不记录凭证，沿用 localhost、Host/Origin 与 API token 保护。

## Acceptance criteria

- [ ] 浏览、刷新或放弃不生成操作；确认发送才异步记录。稳定策略、操作、尝试和快照身份仅作为可选复盘元数据。
- [ ] 保存原始数值、口径、单位、时间、版本、已有费用与覆盖信息；未知保留未知，新金额与数量为 decimal strings，快照不可覆盖。
- [ ] SQLite 系统记录与单写者约束保持；有界积压和慢写、满队列、磁盘错误、不可写数据库不能阻塞发送或改变交易响应。无额外交易调用，无凭证入档，沿用接口安全保护。
- [ ] 普通完整成交可关联查询；成功保存的数据重启后仍在，平仓后历史可查，备份恢复保留快照与关联。
- [ ] 通过对照离线测试证明交易发送次数、顺序、数量、幂等及对冲行为保持一致；不承诺异步记录必达。
- [ ] 本票交付相应持久化、API、界面与离线回归验证；使用单元/API/UI 测试及假交易所，不使用实盘下单验收。
