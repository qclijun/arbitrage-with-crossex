# 02: 条件变化与费用覆盖的诚实展示

Type: task
Status: ready-for-agent

**What to build:** 用户修改数量、市场或模式后，历史明确展示原始预期、实际提交条件及差异，能解释收益是否可比、费用是否计足。

**Blocked by:** 01

实施范围：沿用规格确认的交易流程；留档不得阻止或延迟发送、对冲、补单及恢复，不改变交易准入、幂等或执行数量。采用 SQLite 系统记录和单写者约束，不新增交易调用，不记录凭证，沿用 localhost、Host/Origin 与 API token 保护。

## Acceptance criteria

- [ ] 来源报价与流程已有后续估算分别留存，保留来源与整体/局部范围，不增加报价请求或确认步骤。
- [ ] 条件及假设一致才可作为预期基准；变化后明确不能直接比较，不把旧报价称作最终接受条件。
- [ ] 保留 roll/close、maker-hedge/both-market、返还设置、期限、估值、费率等已有源值。
- [ ] 每项费用分别表达模型覆盖与金额性质，并保留币种、费率、数量/期限和估值依据；预计和实付分列，未知不填零，未计足不称完整净收益。
- [ ] 净计交易/结算费用不重复扣除，Gas 预算与覆盖消耗不双算；不机械按比例分摊固定费用或非线性滑点。
- [ ] 本票交付相应持久化、API、界面与离线回归验证；使用单元/API/UI 测试及假交易所，不使用实盘下单验收。
