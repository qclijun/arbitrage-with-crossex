# 开仓与展期预期收益留档

讨论状态：grilling Q1–Q12 已确认（2026-10-20）。实现状态：未开始。

## 问题与目标

目前机会页收益没有随下单流程持久关联到 Boros 与永续成交。复盘只能事后重建，容易混淆原始报价、费用假设和实际收益。

为普通四腿策略的首次开仓及后续展期保存原始报价、收益口径、各项费用、实际提交条件与成交关联，使用户能查明当时看到了什么、随后改变了什么、最终成交了什么。

## 已确认的产品规则

1. 首次开仓和每次展期分别记录。浏览、刷新机会或打开后放弃不生成交易操作记录；来源报价先随界面流程保留。
2. 用户确认发送时异步留档。失败、拒绝、部分成交及补单也保留；长期保存，不自动过期，与交易数据一起备份和恢复。
3. 关联层级为策略 → 操作 → 报价版本、提交尝试、订单与成交。一次四腿操作可以包含多笔 Boros 提交与永续订单。
4. 来源明确时自动关联。历史或混合仓位无法唯一确定来源时标记待关联，允许事后手动关联和分配数量；不得按时间相近或当前配对比例猜测归属。
5. 同一流程内部分成交和补单沿用操作编号，各有尝试编号。重新发起交易默认新操作；从历史明确选择继续补单时关联原操作。
6. 原始报价不可覆盖。保存来源报价、实际提交参数以及流程本来产生的估算，标记参数差异；不为留档新增重新报价或确认步骤。
7. 参数与假设一致时，来源报价可作为该操作的预期基准；修改数量、市场或模式后标记不能直接比较，不把旧报价称作最终接受的新条件。
8. 原样保存页面收益与费用覆盖情况。未知不填零，未计足费用的页面结果不能改称完整净收益。
9. 留档不是交易前置条件。保存失败不得阻止或延迟发送、对冲、补单和原有恢复；不得影响原有交易准入、订单幂等或执行数量。
10. 失败时显示记录缺失或不完整；原始数据仍在时可补写。原报价已丢失时不以事后重算冒充。
11. Positions 提供策略复盘历史入口，覆盖已结束、失败和待关联操作；当前持仓卡与永续交易详情提供相关记录入口。
12. 展期从持仓确认面板发起，记录该面板已有报价并注明来源；不把新市场的普通开仓报价冒充整个展期的预期。

规则 6–7 是对最初“最终确认报价为基准”的细化：现有流程没有统一的最终四腿报价确认页，不为留档改造交易体验，也不把仅含部分腿的估算冒充完整四腿预期。

## 最小记录内容

### 身份与版本

- 策略、操作、尝试、快照各自的稳定标识；操作类型、来源入口及关联状态。
- 现有 Boros clientOrderId、交易哈希，永续 deal/order/fill 标识及对应数量。一个操作可关联多个执行结果。
- 报价产生、界面观察、用户确认、提交和成交时间分别保存；未知时间保留未知，不用保存时间冒充报价时间。
- 快照结构版本、可取得的应用/计算版本；原始快照不因升级被重算覆盖。

### 报价与计算条件

- 所选机会或展期报价的原始收益值、字段口径和单位，以及其整体/局部覆盖范围。
- 市场、方向、抵押币、到期、单腿名义金额、目标数量、美元估值价格及时间。
- 固定 APR、可成交利差、页面提供的冲击估计、期限、开仓模式、退出模式、费率档位和返还设置。
- 实际接受的提交参数；后续已有估算作为另一个带来源的快照，不覆盖原机会报价。
- 不只保存收益美元数，也不只保存格式化后的界面整数。

### 费用明细

- Boros 交易费、结算费；永续开仓费、预计退出费；现有模型提供的开仓/退出滑点。
- 首次市场入场费、Gas、借款利息、换汇成本等各有覆盖说明；页面未提供时明确未计入或未知，不要求新增外部请求以补齐。
- 每项保留金额、币种、费率、计费数量/期限、估值依据及可取得的数据来源。
- 同时表达是否纳入收益模型及金额性质，例如“已计入（估算）”；已计入、估算、未计入、不适用、未知不能被一个模糊标签替代。
- 实付费用与预计费用分列；已净计的结算/交易费不得重复扣，Gas 预算入账与其覆盖的消耗不得双算。
- 保存源值；新金额与数量字段遵守项目 decimal string 约定，不用浮点重算来替代原始记录。

## 展示与归属

- 历史入口按策略和操作展开：来源预期、条件变更、完成数量、未完成数量、各腿订单及成交费用。
- 实际成交归属于数量份额；不能把共享 HL 等账户总仓位或全部资金费自动算入一笔策略。
- 展期沿用永续时记录沿用份额，不生成虚假的永续成交或重复开仓费用。
- 部分成交保留整笔目标报价并展示完成程度，不把整笔预期当作已完成部分的收益，也不将固定费用或非线性滑点机械按比例分摊。
- 待关联操作可事后分配来源数量；手动关联保留变更记录，不改原始报价或成交。关联不能制造超额归属。
- 条件不一致、局部估算、记录缺失及未计费用直接标明；不得静默补成可比的完整预期。
- 策略已平仓、未成交或失败后仍可从历史入口查询。

## 留档与交易的隔离

- 身份贯穿现有界面和请求作为可选复盘元数据，不用作交易准入、价格有效性或订单幂等键。
- 交易路径不等待报价持久化、补写或展示查询；留档失败不得改变交易响应中的真实执行结果。
- 留档重试只补记录或查询既有订单，不再次发送交易。原有 unknown 探测与单写者执行规则保持有效。
- 满队列、磁盘错误、不可写数据库等留档故障不能向交易传播；不能给交易增加无界后台积压。
- 若错误可由既有交易记录或回包识别，在详情标明缺失；所有证据均丢失时不能保证枚举出该历史尝试。
- 这是允许缺失的异步记录：进程崩溃或存储失败可能丢数据，不承诺每笔均能留存。长期保存只适用于已持久化成功的数据。
- 持久化必须遵守 SQLite 系统记录及单写者约束，不能另开写者或让慢留档挤占交易处理。实施前明确调度与故障隔离方式。
- 复用 localhost、Host/Origin 和 API token 保护，不记录凭证、授权头或密钥。

## 验收条件

1. 页面报价关联到两条 Boros 腿与多个永续订单；撤单转 taker、部分成交和补单不丢关联，也不重复计费。
2. 新开仓及不同批次展期各有快照；沿用永续只记份额。重启后成功保存的关联可读取。
3. 修改大小、市场或模式后，原报价不变，实际参数可查，并明确不可直接比较。
4. roll/close、maker-hedge/both-market、费用返还等输入保持原值；展示能解释哪些退出费用计入、哪些未计入。
5. 未知费用不变零；净额费用与 Gas 信用/消耗不会重复累计。
6. 注入留档延迟、失败和积压时，交易不等待，发送次数、顺序、数量、幂等及对冲结果与未启用留档一致；没有额外交易调用。
7. 保存失败后，仍可用的原始快照可补写；已丢失的报价保持缺失，不生成伪造历史。
8. 共享仓位、历史仓位及多来源展期不凭重建比例自动认领；待关联和事后数量分配可查，不能超额分配。
9. 原交易失败或仓位已关闭后，历史入口仍能查询已保存记录；备份恢复同时保留报价、尝试和成交关联。
10. 验证使用离线单元/API/UI 测试和假交易所，不以实盘下单验收。

## 范围边界与交接

本功能提供预期证据、成交关联和费用查看；全自动资金费/借款/基差归因、历史报价回填、新收益模型及交易策略变更不属于本轮。

现有入口定位已只读核实：机会页到 wizard 未传完整收益；Boros 与永续分别有执行标识，缺共同操作身份；展期入口在 Positions。实施需复用其请求/回包和既有估算，不新增市场操作。

交接：目标与产品决策已收敛，本阶段仅形成规格，功能尚未实现。下一阶段先确定持久化调度与非阻塞故障隔离，再实现身份和快照、执行关联、历史展示及离线验收。不能以副作用留档失败为由阻止交易，也不能以非阻塞为由承诺记录必达。规格为开发与验证依据；实盘证据和调查细节留在本机忽略目录，不进入提交。仍需通过实现审查证明原有交易行为保持一致。
