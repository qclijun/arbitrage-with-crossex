# 拆票草案：开仓与展期预期收益留档

Status: approved-and-published

依据本目录规格；以下方案已获用户确认，并按编号发布为独立本地工单。所有工单使用离线测试和假交易所验收，不改变交易准入、报价策略或执行数量。每票同时交付所需持久化、接口、界面和测试，不另设横向数据库票或最终测试票。

## 01：正常四腿开仓的预期留档与历史查询

Blocked by: None

从机会页到确认发送保留原始报价，成功开仓后可在 Positions 历史及持仓、永续交易详情查看同一操作的报价、提交条件、两条 Boros 腿和多个永续订单/成交。首次实现前明确并记录单写者调度与故障隔离方案。

- 浏览、刷新或放弃不生成操作；确认发送才异步记录。稳定策略、操作、尝试和快照身份仅作为可选复盘元数据。
- 保存原始数值、口径、单位、时间、版本、已有费用与覆盖信息；未知保留未知，新金额与数量为 decimal strings，快照不可覆盖。
- SQLite 系统记录与单写者约束保持；有界积压和慢写、满队列、磁盘错误、不可写数据库不能阻塞发送或改变交易响应。无额外交易调用，无凭证入档，沿用接口安全保护。
- 普通完整成交可关联查询；成功保存的数据重启后仍在，平仓后历史可查，备份恢复保留快照与关联。
- 通过对照离线测试证明交易发送次数、顺序、数量、幂等及对冲行为保持一致；不承诺异步记录必达。

## 02：条件变化与费用覆盖的诚实展示

Blocked by: 01

用户修改数量、市场或模式后，历史明确展示原始预期、实际提交条件及差异，能解释收益是否可比、费用是否计足。

- 来源报价与流程已有后续估算分别留存，保留来源与整体/局部范围，不增加报价请求或确认步骤。
- 条件及假设一致才可作为预期基准；变化后明确不能直接比较，不把旧报价称作最终接受条件。
- 保留 roll/close、maker-hedge/both-market、返还设置、期限、估值、费率等已有源值。
- 每项费用分别表达模型覆盖与金额性质，并保留币种、费率、数量/期限和估值依据；预计和实付分列，未知不填零，未计足不称完整净收益。
- 净计交易/结算费用不重复扣除，Gas 预算与覆盖消耗不双算；不机械按比例分摊固定费用或非线性滑点。

## 03：失败、部分成交与继续补单的操作追踪

Blocked by: 01

历史能够解释一次开仓从失败或部分成交到继续补单的全过程，并诚实表达记录缺失与可补写范围。

- 拒绝、失败、部分成交、撤单转 taker 和补单保留操作身份，各有尝试身份，关联所有订单及成交且不重复计费。
- 同流程补单沿用操作；重新发起默认新操作，从历史明确选择继续补单才关联原操作。
- 展示目标、完成和未完成数量，不把整笔预期当作已成交部分收益；未成交或失败也能从历史查询。
- 留档重试只补记录或查询既有订单，不重发交易；unknown 探测和既有恢复保持原样。
- 有证据时标明缺失/不完整，原始快照仍在则可补写；已丢失报价保持缺失，全部证据丢失时不声称能枚举尝试。
- 故障注入覆盖发送、对冲、补单和恢复，验证留档不增加等待或无界积压，执行结果与未启用留档一致。

## 04：按批次记录展期与永续沿用份额

Blocked by: 02, 03

从 Positions 持仓确认面板展期后，用户可在策略历史查看每个展期批次的面板原报价、实际条件、尝试与执行结果。

- 首次开仓与每次展期分别记录；标明面板报价来源、已有估算范围和条件差异，不用新市场普通开仓报价冒充整个展期预期。
- 沿用永续时仅记录已有数量份额，不制造成交或重复收取开仓费用。
- 展期部分成交、失败和补单沿用已定义的操作/尝试规则；成功持久化的数据重启及备份恢复后可查。
- 只有来源唯一明确才自动关联；共享、历史或多来源仓位保留待关联状态，不按时间或当前配对比例猜归属。
- 离线覆盖多批展期、沿用永续及异常执行，验证无新增市场操作。

## 05：待关联操作的手动数量分配与审计

Blocked by: 03

用户可从历史找到来源不明的操作，手动关联策略和成交数量份额，并查看更改记录。

- 保留待关联入口；只有唯一证据支持时自动归属，不以相近时间、共享账户仓位或当前配对比例认领。
- 支持同一执行结果的数量份额分配，拒绝超额归属；关联调整保留审计，不改原报价或成交。
- 不把账户全部永续仓位或资金费算进单笔策略；关联动作不发交易。
- 失败、已结束及历史操作均可处理，重启及备份恢复保留分配和变更记录。
- 以共享仓位、多来源与部分数量案例离线验证；展期上线后复用同一归属规则，不依赖展期功能才能交付本票。
