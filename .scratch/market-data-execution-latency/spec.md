# 降低盘口与执行延迟风险：首期实施规格

Status: ready-for-agent
Updated: 2026-10-16 Asia/Taipei
Source: [降低盘口与执行延迟风险决策地图](map.md)

## Problem Statement

Maker 已成交而 Taker 对冲尚未成交时，交易者承担永续价格净敞口。现有路径可能在发现成交、取得对冲必需参考价及发送对冲之间，等待不参与当前动作的 Maker 行情；签名请求的连接建立与排队也可能增加等待。用户优先缩短这段暴露，POC 拒绝率和建仓耗时为次要指标。

现有短时只读样本不足以证明真实下单提速。请求往返、源快照年龄、缓存驻留、本地成交确认响应和真实成交之间的经济暴露还缺少可独立验证的证据；对冲订单已登记或预留也不代表暴露已经消失。优化若造成重复获取、超额对冲、错误重发或绕过校验，即使更快也不可接受。

## Solution

先建立轻量、可归因的分段计时和原路径基线，再分别验证引擎专用签名连接池、当前 deal 内无关 Maker 行情等待消除，以及二者组合。交易者能看到已有成交何时被确认、对冲何时登记和发起、为何等待，以及当前证据能否证明暴露改善。

行情失效时沿用现有报价暂停、取消优先、失败预算与状态规则；Maker 行情不能单独阻塞不依赖它的已成交对冲，但对冲自身缺少必需参考价时仍保留校验并报告等待。恢复只解除对应数据依赖，不覆盖其他安全约束。优化独立可关闭，是否启用由离线安全证明、只读对照及资源门槛决定；真实收益另由自然计划交易证明。

## User Stories

1. As a 交易者, I want 优先缩短 Maker 已成交后的未对冲等待, so that 永续价格净敞口更早得到处理。
2. As a 交易者, I want 区分本地确认响应与真实成交暴露, so that 登记更快不会被误当成风险已消失。
3. As a 交易者, I want 原路径先有可复核基线, so that 每项优化的效果能够独立比较。
4. As a 交易者, I want 仅引擎的签名请求使用专用连接池, so that 本期变更范围明确且不被界面请求竞争混淆。
5. As a 交易者, I want 订单观察、下单、撤单和下单后确认均被计时, so that 等待能归因到实际阶段。
6. As a 交易者, I want 保持原有代理或直连路径, so that 连接失败不会悄悄改变网络路径。
7. As a 交易者, I want 继续使用原有签名、序列化和 TLS 校验, so that 提速不改变认证与交易请求含义。
8. As a 交易者, I want 超时、重置和 5xx 仍按 UNKNOWN 处理, so that 未查明的订单不会被自动重发。
9. As a 交易者, I want 下单确认查询失败后继续观察原订单, so that 已接受的订单不会被重复创建。
10. As a 交易者, I want 连接数由排队和资源证据决定, so that 连接池不会靠无界扩张取得表面收益。
11. As a 交易者, I want 凭据切换等待安全条件和在途请求完成, so that 原账号订单不会被新账号错误接管。
12. As a 交易者, I want 失败候选和退役客户端释放新增资源, so that 热切换不会持续泄漏连接。
13. As a 交易者, I want 对冲不等待当前动作不依赖的 Maker 行情, so that 慢源不会增加可避免的裸露时间。
14. As a 交易者, I want 缺少对冲必需参考价时仍执行最小名义金额校验, so that 紧急路径不会凭猜测下单。
15. As a 交易者, I want dust 与真正缺价分别处理, so that 不可提交的零碎数量不会被累计成错误故障。
16. As a 交易者, I want 报价暂停和既有保护性撤单规则保持, so that 无关等待优化不会移除已有风险保护。
17. As a 交易者, I want 缺价等待首次发生时获得原因、数量和持续时间, so that 我能判断是否需要通过现有入口介入。
18. As a 交易者, I want 持续告警沿用去重和节流, so that 等待可见且不会被重复通知淹没。
19. As a 交易者, I want 参考价恢复后复核订单和最新意图再继续, so that 恢复不会忽略 Stop、Convert 或改价。
20. As a 交易者, I want 对冲参考价恢复与 Maker 行情恢复分别记录, so that 跳过读取不会伪造恢复事实。
21. As a 交易者, I want 单写者和每 tick 最多一次交易写请求保持, so that 提速不引入交易写入竞争。
22. As a 交易者, I want 未知订单冻结、取消优先和写前登记保持, so that 减少等待不增加重复获取或超额对冲。
23. As a 交易者, I want 明确区分源年龄、缓存驻留和网络往返, so that 请求成功不会被误当成行情足够新。
24. As a 交易者, I want 无法核实的时钟偏差和成交归因显示 UNKNOWN, so that 报告不会制造精确性。
25. As a 交易者, I want 查看分操作与冷/热连接的 p50、p95、最大值及失败数量, so that 平均值不会掩盖长尾。
26. As a 交易者, I want 池化与无关等待消除分别验收, so that 我知道收益及回归来自哪项改动。
27. As a 交易者, I want 只读对照遵守现有频率和限流预算, so that 验收不会增加额外交易或请求压力。
28. As a 交易者, I want 只有后续获授权的自然交易用于真实收益验证, so that 测速不会成为额外下单理由。
29. As a 交易者, I want 任一安全回归直接使验收失败, so that 延迟收益不能抵消交易错误。
30. As a 交易者, I want 两项优化能够独立受控回退, so that 定位问题时保留有效优化与原有账本。
31. As a 交易者, I want 本机观测只保留必要脱敏元数据, so that 验收不复制凭据和完整交易请求。
32. As a 交易者, I want 观测时间、磁盘和缓冲均有上限, so that 记录本身不会拖慢交易或无界占用资源。
33. As a 交易者, I want 观测丢弃与写入失败可见, so that 缺失证据不会被当作完整验收样本。
34. As a 实现维护者, I want 沿用现有引擎模拟与账本测试入口, so that 安全证明基于真实执行边界而不是复制实现。
35. As a 实现维护者, I want 每阶段保存参数、样本和结论依据, so that 后续能够复核启用与回退决定。

## Implementation Decisions

### 1. 范围与分阶段交付

- 本期修改责任限于引擎观测、引擎专用签名客户端与资源生命周期、当前 deal 的行情依赖等待、既有告警输出及本机验收报告。保留现有路由写意图并唤醒引擎的边界，不新增交易写者。
- 顺序为：仅计时及开销验收 → 原路径基线 → 分别实现和验证池化、无关等待消除 → 验证组合 → 满足条件后的受控试用。池化和等待优化必须分别可关闭；不得将二者捆绑成不可分辨的结果。
- 规格完成只表示可交接实现。启用需通过本规格规定的安全、性能、参数和资源门槛；自然实盘观察需后续另行授权。样本不足或证据无法核实，不以默认通过补齐。

### 2. 引擎专用签名传输

- 专用池覆盖引擎订单观察、下单、撤单和下单后确认。界面及其他签名消费者、Spot/Futures、候选凭据验证和无签名公共客户端保持原传输；原生公开盘口已有独立池不重复改造。
- 保留当前直连/代理选择、端到端 TLS 校验、SDK 签名与时间戳生成、序列化、十进制解析和默认请求头。池仅持有连接配置，不缓存签名请求或账号数据；失败不得自动绕过代理。
- 保留现有 15 秒请求超时。该数值不是已证明涵盖全部排队、建连和代理阶段的端到端期限；测量须标明计时边界与未覆盖阶段。
- 连接数必须有上限，以离线并发和只读对照的排队、长尾、连接/文件描述符及资源证据定值，记录选值和启用依据。不得照搬探针的两条连接，不自动扩池；参数未落实前保持池化禁用。
- 超时、连接重置、5xx 及非确定业务拒绝仍为 UNKNOWN，由原 client/order 标识探测。不得增加交易写请求自动重试，不因一次故障自动换池重发下单或撤单。已接受下单而确认查询失败时，继续观察原订单。

### 3. 生命周期与切换

- 候选凭据验证通过且确认没有活跃 deal 后才切换客户端；维持现有验证与再次检查的顺序。候选验证本身不纳入引擎池化。
- 旧客户端停止接收新请求，在途请求结束后释放连接；验证失败、忙状态退回或放弃切换时释放新增资源。不得使原账号在途订单的观察落到新账号。
- 代理配置与传输开关切换也使用受控生命周期，不继续向退役池派发请求，不中断在途请求。正常关闭应释放新增资源。

### 4. 当前 deal 的对冲等待

- 保持 OBSERVE → PROJECT → DECIDE → ACT、单写者、每 tick 最多一次交易写请求、纯决策与写前登记。数量及金额继续使用十进制字符串，观测不得改变交易账本的系统记录地位。
- 只有当前最终动作不依赖 Maker 报价或新 A 单获取时，才消除 Maker 行情读取的阻塞。不能把“存在未预留义务”直接等同于“本 tick 必然提交 B”；取消、模式变化、冻结、退避与 sizing 仍可优先。
- 单纯并发读取但仍等待全部结果不能算通过。并发只读若使用，须基于相同意图和投影，结果分别携带状态/时间且失败隔离；只有实际依赖的结果可阻塞当前动作。保持跨 deal 调度现状。
- 对冲所需参考价仍用于既有最小名义金额等校验，不新增市价限价带或改动 Taker 类型。必需参考价缺失时不得暗用旧缓存、备用源或零值哨兵绕过校验；数量向下取整、不向上凑单，dust 不算缺价故障。
- await 后重读最新意图；Stop、Convert、改价或报价模式变化使旧上下文失效，等待下一 tick 按新意图重算。保留 UNKNOWN/PENDING/quarantine 的 placement 冻结、既有取消例外、取消优先、退避及失败预算。

### 5. 行情失效、等待与恢复

- 不新增源年龄硬门槛、失效自动撤单或转 Taker 触发。保留现有报价暂停和全部既有失败/转换规则；“报价暂停”自身不是撤单，也不等于 deal 停止。
- 现有保护不得被“不新增”误删：当前最优价路径已有持续盘口故障达 30 秒且订单观察条件允许时的撤单规则，以及持续缺少对冲参考价时的失败计数、退避和 HALTED 行为，均按既有适用范围保留。2 tick、15 秒、20 次、绝对期限和既有经济性约束不改变；四腿专属规则不得扩展到普通 deal。
- 首次识别可提交的已确认成交义务因缺少必需参考价受阻时，报告原因、未预留义务数量、可验证的实际未对冲数量及持续时间。不能验证的实际数量为 UNKNOWN。持续报告沿用既有告警渠道及去重/节流，不新建通知系统。
- 不新增“等够时间就绕过校验”、自动换源、反向平仓或状态变化政策；原有状态规则仍有效。人工介入使用现有受支持入口，不与引擎另行并发下单。不承诺固定秒数内完成对冲。
- 当前必需参考价实际取得且通过既有有效性检查后，重新确认订单、重算投影并复核最新意图，再按原规则自动继续；不新增人工解锁或连续成功次数要求。仅解除对应依赖，其他冻结、退避、取消优先和模式约束继续有效。
- 跳过 Maker 读取不能清除旧 outage、伪造恢复或重置故障持续时间；B 参考价恢复不能代表 Maker 恢复。源时间缺失仍为 UNKNOWN；本地组装、缓存命中或请求成功均不是源新鲜度证明。

### 6. 最小观测契约

- 关联字段：一致化脱敏的 deal、leg、client/order/fill 标识，源 venue/market、请求用途、tick/attempt、缓存键/命中、意图前后状态与决策原因、ok/reject/unknown。保留数量单位、合约换算依据、累计成交及预留增量，以便去重和归因；多 deal、手工单或聚合成交无法可靠分摊时标 UNKNOWN。
- 时间字段：本机单调时钟的阶段起止及 UTC 锚点；订单观察、新累计成交确认、决策、写前登记、请求发送入口、回执、后续确认；源原始时间/单位及可信状态、本地接收/缓存写入/使用时刻。区分源年龄表观值、缓存驻留、请求 RTT、池排队及决策至发送；无法独立观测的阶段必须注明，发送入口不得伪称网卡实际发送。
- 本地对冲响应沿 Maker 新累计成交确认 → B 写前登记 → B 请求发送入口 → B 回执分段。真实暴露按可归因的实际成交量重建净基础币数量 E(t)，报告峰值、等待持续时间和 ∫|E(t)|dt。未预留义务扣除 B 预留；真实暴露必须使用 B 已成交量，二者不得混用。
- 跨 venue 成交时间钟差未校准时，仅报告表观差及误差 UNKNOWN；缺源时间、未来值、单位混淆、本地墙钟跳变不能伪造成精确源年龄或精确经济暴露。盘口长期未变化不单独等于故障。
- 同时报告 POC 拒绝率、Maker 实际成交身份、超额对冲、残余 dust、错误/限流、样本数、排队及资源统计，均标明分母、归因和证据缺口。

### 7. 观测资源与保留

| 项目 | 已确认边界 |
| --- | --- |
| 新增本机结构化明细 | 7 天，全部明细合计不超过 100 MiB |
| 新增聚合验收报告 | 30 天，全部报告合计不超过 10 MiB |
| 异步观测缓冲 | 不超过 1 MiB，不阻塞交易 loop |
| 稳态进程 RSS 增量 | 不超过 32 MiB，且不得无界增长 |

- 时间与容量取先到者，轮转最旧的本次观测副本。不删除或改变 SQLite 账本、既有日志或历史交易数据。记录队列丢弃及轮转计数，不缓存无界完整响应。
- 不写凭据、签名、认证头、完整请求/响应或原始账户标识；关联键一致化脱敏，保留关联能力。
- 队列满或写入失败可以丢弃观测，但必须计数并经既有告警渠道报告；相应验收片段为 UNKNOWN，不能以缺失证据作为通过依据。观测故障不得阻塞交易。

### 8. 独立回退

- 池化与无关行情等待消除独立显式关闭；受控试用出现失败条件时保留证据，回退对应优化，不将性能收益抵消安全失败。
- 等待在途请求完成，保留当前意图与账本；不强制停引擎、不打断请求、不自动换池重发交易。无法立即安全切换时告警并维持既有探测/恢复规则，不承诺瞬时回退。
- 连接池参数及基线证据是启用前的实施输出，不在本规格伪造具体连接数；落实后补入规格或附属验收记录，并保留选择理由。

## Testing Decisions

### 1. 测试边界与现有先例

- 主入口沿用现有 tickPair、可控 Venue、VirtualClock 和临时 SQLite Store 的组合，以及现有引擎模拟不变量检查。现有循环情景测试已覆盖成交后追补和 await 中指令变化，盘口故障测试已区分仅行情不可用与订单也不可读，并覆盖现有 30 秒撤单和缺价 HALTED 行为。
- 好测试断言外部订单调用、数量、可观察动作/原因、账本事实和报告，不复制内部谓词或绑定私有 helper 的调用次序。用可控 promise 证明 B 可发时不再等待慢 Maker 源，避免以不稳定墙钟睡眠证明逻辑收益。
- 保留纯决策模拟作为安全补充；连接复用、代理路由、UNKNOWN 及释放责任在既有 Venue/客户端边界补充离线适配器与本地可控传输测试，不能仅靠 FakeVenue 声称真实传输契约已覆盖。
- 观测在其有界写出边界测试脱敏、时间、容量、队列溢出、轮转与写入失败，再通过引擎入口验证缺价首次报告、持续去重、恢复分离和交易不受阻塞。优先复用现有依赖注入，不为本期创建新的调度框架或多层测试框架。
- 用户于 2026-10-16 回复“按推荐”，确认以上测试边界；不重开已确认业务取舍。

### 2. 必须通过的离线反例

| 场景 | 通过条件 |
| --- | --- |
| Maker 慢、B 必需数据已就绪 | 当前动作不依赖 Maker 时，B 不再等待该请求；保留所有高优先约束 |
| B 必需参考价缺失及恢复 | 不用旧价或零值绕过 sizing；等待可见；恢复后复核意图与原有模式 |
| 部分成交、撤单在途新增成交 | 单调合并并追补真实新增义务，不重复获取、不超额对冲 |
| dust、lot、minSize/minNotional 邻界 | 不向上凑单，不将 dust 计成缺价失败 |
| UNKNOWN、PENDING、quarantine | placement 冻结及原标识探测保持；只允许既有取消例外 |
| await 中 Stop、Convert、改价 | 旧上下文失效，不基于混合意图下单 |
| 跳过 Maker、旧 outage、独立恢复 | 不重置或清除未被证实恢复的故障；既有保护不消失 |
| 超时、连接重置、5xx | 保持 UNKNOWN；不自动重发交易；下单后确认失败不重复创建 |
| 直连/代理、认证与序列化 | 路径、TLS、签名、十进制和默认头契约保持，不泄露认证材料 |
| 凭据/代理切换与失败候选 | 不串账号；退役后不派新请求；在途完成后释放，无新增资源泄漏 |
| 资源耗尽、队列满、轮转/写入失败 | 缓冲有界、交易不阻塞、丢弃可见、缺证片段 UNKNOWN |
| 源时间缺失/未来值/单位错误、墙钟跳变 | 不将不可核实数据算成零年龄或精确暴露 |
| B 已预留未成交、多 deal 成交归因 | 真实暴露不因预留归零；无法映射的数量 UNKNOWN |

### 3. 观测开销验收

- 仅计时相对原路径，以离线同输入至少 3 组配对、每组至少 1000 个 tick 测量。合并及每组 tick p95 开销均不得超过 max(对应原 p95 的 5%, 1ms)。
- 稳态 RSS 增量不超过 32 MiB，且不得无界增长；计时、告警及写出开销进入评估。超限调整后重验，不能拿被观测拖慢的版本当作优化收益基准。

### 4. 同机只读对照与池化门槛

- 至少 3 组交替时段；每种配置、每个主要操作类别、每组至少 100 个成功样本。先仅计时基线，再分别测试两项优化及组合；对无法由只读请求触发的对冲行为，以离线场景取证，不制造真实写操作。
- 固定可比的机器、账号配置、直连/代理路径及操作类别；冷/热连接、成功/失败分层。失败和限流不得从总请求分母删除；遵守既有允许的只读频率和限流预算，不为凑数加速。数量不足的层不外推。
- 每类报告 p50/p95/max、样本数、错误/限流、排队和资源占用，不用混合类别均值掩盖长尾。池化须逐主要操作类别满足以下全部门槛：

| 指标 | 启用门槛 |
| --- | --- |
| 合并 p95 | 相对基线改善至少 10% |
| 分时段 p95 | 至少 2/3 时段改善至少 10% |
| 合并 p50 | 恶化不超过 10% |
| 任一时段 p95 | 恶化不超过 max(对应基线 p95 的 10%, 20ms) |
| 安全、错误、限流和资源 | 安全反例全部通过，无可归因的新错误/限流或资源越界；连接参数有证据且有上限 |

- 性能预算未达为 FAIL；样本不足、证据缺失或混杂因素未排除为 UNKNOWN，均不启用对应池化。通过是本机受控试用预算，不是统计显著性声明、长期 SLA 或实盘收益保证。

### 5. 后续自然交易与失败判定

- 只在另行授权的自然计划交易观察创建、确认、撤单及 Maker 成交至对冲阶段，不额外发单或人为制造故障。按实际数量报告本地响应、真实暴露峰值/持续时间/积分和时钟、归因局限；样本过少不宣布通过百分位或收益保证。
- 重复获取、超额对冲、未知结果后重发、冻结/取消优先或校验被绕过、凭据串用、交易语义变化、可归因的新错误/限流或资源越界均直接 FAIL。延迟改善不能抵消。出现失败按独立受控回退执行；缺证则 UNKNOWN，不默认通过。
- 实现后按变更执行项目离线类型与测试检查；涉及网页时再验证网页测试与生产构建。真实账户 live tests 不作常规验证，本次生成规格不运行产品测试或实盘操作。
