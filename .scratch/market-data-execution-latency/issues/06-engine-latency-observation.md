# 06: 引擎分段观测可用且不拖慢交易

Status: ready-for-agent
Progress: resolved
Assignee: Codex
Source: [首期实施规格](../spec.md)
Blocked by: none

**What to build:** 在原路径保持交易行为的前提下，将成交确认、决策、登记、发送入口和回执等必要阶段接入本机有界观测，使交易者和验收者可以关联一次对冲响应。

**依赖工单：** 无，可立即开始。

## Acceptance criteria

- [x] 接通引擎、既有适配器和观测写出，保留关联键、源/缓存时间及可验证状态、成交/预留数量和单位；UNKNOWN 不显示成零或已完成。
- [x] 原签名客户端及行情等待顺序保持，先取得纯观测版本，不提前加入两项优化。
- [x] 单调时钟与 UTC 锚点分开；本地发送入口不冒称网卡发送，源时间缺失和跨钟不确定性显式保留。
- [x] 明细 7 天/100 MiB、报告 30 天/10 MiB、缓冲 1 MiB；保留期限与容量取先到者。脱敏、轮转、写入失败与队列丢弃可验证，账本和既有历史不受影响。
- [x] 通过主要引擎入口验证动作/数量/账本不回归，补充观测边界测试；至少 3 组同输入配对，每组 1000 tick，合并与各组 p95 开销均不超过 max(原 p95 的 5%, 1ms)，稳态 RSS 增量不超过 32 MiB 且无无界增长。
- [x] 观测缺证片段 UNKNOWN，不阻塞交易，不以拖慢后的版本夸大优化收益。
- [x] 最小观测包含意图变化、ok/reject/unknown、缓存命中/键与源 venue/market；保留一致化脱敏的 client/order/fill 关联及数量单位，不记录凭据、签名、认证头、原始账户标识或完整请求/响应。
- [x] 新增观测失效不得改变交易语义；确认成交到登记、发送入口及回执均有可验证阶段或显式 UNKNOWN，预留不当成成交。

## Shared constraints

- 沿用已确认的引擎 tick、可控 Venue、临时 SQLite 账本主测试入口；涉及传输与观测时补充其边界测试。断言可观察行为、订单数量、账本及报告，不复制内部实现。
- 保留单写者、每 tick 最多一次交易写请求、写前登记、取消优先、未知订单冻结、十进制数量与既有故障恢复；本票不得夹带新的交易风险政策。
- 按变更执行项目类型检查和离线测试，必要时验证网页测试与构建；不运行真实账户 live tests 作为常规验证。
- 所有新增观测遵守规格脱敏、保留、容量及故障处理规则，不删除或改变既有账本、日志或历史交易数据。
- 本票发布只授权后续按流程实施，不自动部署、重启、启用优化或真实交易。完成时记录实现、测试、测量及未通过项；无充分证据时保留 FAIL/UNKNOWN，不默认验收通过。

## Answer

2026-10-23：RSS 门禁复测通过，06 resolved。

- 原失败原因：约 140 MiB 的 RSS 台阶是 V8 动态扩大新生代后保留的高水位。纯 JS 同形状分配也会出现，固定新生代后消失；不来自观测器，也不主要来自 SQLite 语句准备。
- 在 `1271d2d` 对照 `1fe452cf`，基准脚本和门禁不变，两组都设 `NODE_OPTIONS=--max-semi-space-size=1`：三组 p95 开销 +0.19～+0.29 ms（预算 1 ms），共同稳定检查点 120/80/120，稳态 RSS 增量 24.95/25.11/11.71 MiB（上限 32），账本一致，无后续增长否决。
- 局限：生产用默认参数，默认参数下观测器的增量没有直接测出；离线合成样本不证明实盘延迟或暴露。
- 证据：[复测报告](../../../docs/validation/engine-observation-rss-2026-10-23.md)。没有部署、重启、启用观测或交易。
