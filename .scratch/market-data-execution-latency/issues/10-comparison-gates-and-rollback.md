## Acceptance criteria

- [ ] 沿用已交付采集/报告入口，以相同机器、账号配置、网络路径和操作类别做 3 组交替对照，不创建额外真实交易；无法由只读触发的对冲分支用离线可控场景取证。
- [ ] 逐主要只读操作类别，池化合并 p95 和至少 2/3 时段改善至少 10%；合并 p50 恶化不超过 10%；任一时段 p95 恶化不超过 max(基线 p95 的 10%, 20ms)。报告全部样本、错误/限流、排队与资源。
- [ ] 原路径开销、安全反例及观测资源门槛保持通过，验证组合不会让单项通过掩盖组合回归；冷/热不足层、外部混杂或缺证仍 UNKNOWN。
- [ ] 最终池连接数及连接/文件描述符边界有基线、并发与只读对照证据，记录选值及适用配置；不达标或证据不足不得启用。
- [x] 重复获取、超额对冲、未知后重发、绕过冻结/取消优先/校验、凭据串用、交易语义变化、可归因的新错误/限流或资源越界直接 FAIL，不能被延迟收益抵消。
- [x] 两个开关各自和组合的受控退役可验证：等在途结束、保留意图/账本、不强停引擎、不重发交易；无法立即安全切换时告警并维持原探测。
- [x] 保留可复核报告与结论，区分实现完成、证据通过与启用资格；本票不自动部署/启用，不执行自然交易。不足时保留未通过测量里程碑，不以工具交付替代真实证据。
- [x] 留下后续另行授权自然交易的观测清单，真实下单及经济暴露收益保持待验证；不为填报告额外下单。
- [ ] 每配置、每主要操作类别、每组至少 100 个成功样本；失败和限流仍在总请求分母，冷/热分层，数量不足不外推；不提高既有允许只读频率或突破限流预算。
- [ ] 仅观测开销至少 3 组、每组至少 1000 tick；合并和每组 p95 开销不超过 max(原 p95 的 5%, 1ms)，稳态 RSS 增量不超过 32 MiB 且无无界增长。新增明细 7 天/100 MiB、报告 30 天/10 MiB、缓冲 1 MiB 继续有效。

- 按变更执行项目类型检查和离线测试，必要时验证网页测试与构建；不运行真实账户 live tests 作为常规验证。

- 本票发布只授权后续按流程实施，不自动部署、重启、启用优化或真实交易。完成时记录实现、测试、测量及未通过项；无充分证据时保留 FAIL/UNKNOWN，不默认验收通过。
