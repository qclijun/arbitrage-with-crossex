# 02: 增量补读加 3 天重叠比对，长窗口重启后很快可排名

**What to build:** 每轮只读每条腿最新缺失的数据，不再每轮重下整年。重启后首轮补读完，7/30/90/180/365 天窗口就能重新排名；平时币安/Bybit/OKX 的请求量也大幅下降。读取范围是“已存最后一条记录往前 3 天”到当前截止点，所以停机超过 3 天也会补齐缺口。已存段加本轮补读段，在下列证明都成立时，可以算完整且新鲜的窗口；每段在页面和 API 里显示自己原来的核验时间，不改成新时间。

**Blocked by:** 01

**Status:** ready-for-agent

这是对 08/09 历史契约的有意修改（用户 2026-11-01 确认）：原规则要求整个窗口在本小时内由同一次读取证明，不允许跨截止点拼接。

拼接窗口可以算完整且新鲜，必须同时满足：

1. **重叠一致**：3 天重叠段内，补读记录与已存记录逐条一致（结算时间、费率、结算周期）。
2. **无缺口**：已存段与补读段之间不缺结算点，也没有重复。
3. **补读段新鲜**：补读段的读取和核验都在本小时内，核验距今不超过 15 分钟。
4. **全量复核未超期**：最近一次复核未超过 7 天（复核见 03；在 03 完成前，首次全量下载算作一次复核）。

结算周期变化的处理：每条记录按当时的结算周期解释，规则本身就是按时间分段的。交易所以后改周期，只是新增一个规则分段，旧记录不作废。只有当交易所对**已存期间**给出的规则与已存的不一致时（现有的 `historical-policy-changed` 信号），才按下面的不一致处理。

不一致的处理：重叠段比对失败、已存期间规则冲突、出现缺口或重复，都把这条腿隔离，即不能排名、不能开仓，页面给出原因。然后丢掉这条腿的已存记录，整段重下；重下完成并通过核验后才解除隔离。

- [ ] 补读起点 = 已存最后一条记录往前 3 天；停机超过 3 天时一并补齐缺口
- [ ] 上述 4 个条件同时满足时，拼接窗口在排名和服务端开仓复核中都算完整且新鲜，两处用同一套规则
- [ ] 任一条件不满足，窗口按现有规则返回不可用原因，不补 0，不改时间
- [ ] 周期向前变化时保留旧记录，按各自的规则分段解释；已存期间规则冲突时隔离并重下
- [ ] 隔离状态和原因在页面与 API 可见；重下完成并核验后自动解除
- [ ] 币安/Bybit/OKX/Hyperliquid 都改为增量补读；整年下载只在首次、隔离重下和缓存被丢弃时发生

- [ ] 离线测试覆盖：重叠一致、费率或时间不一致、缺口、重复、停机超过 3 天、周期向前变化、已存期间规则冲突、隔离后重下解除；记录重启后首次可排名的轮数
