# 03: 每周复核最近 30 天

**What to build:** 每条腿距上次复核满 7 天，就重下最近 30 天，与已存记录逐条比对，用来发现交易所事后修正的历史记录。复核任务错开安排在每轮预算内，不集中爆发，也不挤掉常规补读。比对一致就更新这条腿的复核时间；不一致按 02 的规则隔离，并整段重下。页面显示每条腿上次复核的时间。

**Blocked by:** 02

**Status:** ready-for-agent

超期规则（默认做法，用户审阅拆分时未提异议）：超过 7 天还没复核完的腿，只有补读段能证明的窗口仍可排名；更长的窗口暂停排名，标“待复核”，复核完成后自动恢复。

- [ ] 满 7 天的腿进入复核队列，重下最近 30 天并逐条比对；各腿复核时间错开
- [ ] 复核占用的请求在每轮预算内，常规补读优先，复核排不进时顺延到下一轮
- [ ] 比对一致更新复核时间；不一致按 02 隔离并整段重下
- [ ] 超期未复核时，补读段以外的长窗口暂停排名并显示“待复核”；服务端开仓复核规则相同
- [ ] 页面与 API 显示每条腿上次复核的时间和状态
- [ ] 离线测试覆盖：到期入队、预算不足顺延、复核一致、复核发现修正、超期暂停与恢复
- [ ] `yarn verify` 和 `yarn --cwd web build` 通过；不重启线上服务，不发真实交易请求
