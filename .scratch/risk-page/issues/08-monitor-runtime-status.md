# 08: 监控服务、心跳与通知送达状态

**What to build:** 交易者在 Risk 分别看到终端读取状态、独立监控最后完成时间/心跳和通知队列/送达证据，能够识别监控失联或通知失败，且不会把打开浏览器当成监控正常。

**Blocked by:** 01: Risk 页面与 Gate 保证金、清算风险。

**Status:** done

- [x] 接入 `service.http_ok`、`monitor.heartbeat_age_s`、`notify.last_success_at` 三项检查及全部关联指标。
- [x] 复用终端健康读取与现有独立监控心跳/状态；通过最小只读、scope 绑定的适配暴露批准的完成时间、连续失败、队列和确认送达字段。
- [x] 终端 HTTP 成功、collector 最近完整采集和 Telegram 确认送达分别显示。浏览器成功次数、托管通知 connected 状态或本机服务活着不能替代独立监控证据。
- [x] 对旧报告/状态先核验终端来源、配置身份、root、支持的子账户与相应操作范围；无法确认归属的元数据保持 UNKNOWN。全局运行状态明确标明其范围，不伪装成另一钱包的监控。
- [x] 心跳/最后完成时间保留 producer 时间，不采用文件读取、镜像传输或页面刷新时间；缺失、畸形、未来与过期证据按契约处理。
- [x] 采集 complete 只表示必需请求完成，不表示全部风险指标已知；新鲜但不完整的采集不能给出整体安全结论。
- [x] 通知成功只来自已有确认送达记录；没有部署、没有状态或范围不明确均不是零失败/零待发送。
- [x] 刷新不启动、重启、修改或解锁监控，不写 heartbeat/state，不推进通知去抖、不测试发信、不消费通知队列。
- [x] 接口沿用现有身份与 Host/Origin 保护，仅返回批准的字段；API token、Telegram token/chat 配置、代理密钥和原始状态内容不返回客户端。
- [x] 页面/服务合成测试覆盖终端可读但 monitor 过期、heartbeat 新鲜但 last-complete 过期、状态缺失、未来时间、送达失败、待发送及scope切换，并断言完全只读。
- [x] 本票范围的独立演示与离线检查通过；当整个依赖图完成后，执行父规格要求的全目录/全指标覆盖、共享查询行为、账户隔离、规则一致性及生产构建验收，不将其他分支设成本票的实现前置条件。
