# 06: 到期、展期与资金费缺口风险

**What to build:** 交易者在 Risk 查看到期倒计时、后续展期机会、共存阶段保证金需求与实际资金费缺口；只有完整证据证明远离到期时，相关展期检查才暂停。

**Blocked by:** 04: ETH 对冲、价差与执行残留风险。

**Status:** ready-for-agent

- [ ] 接入 `rollover.days_to_maturity`、`rollover.next_net_apr`、`rollover.incremental_margin_usd`、`rollover.uncovered_funding_seconds` 四项检查及全部关联指标。
- [ ] 复用已建立的精确策略腿/市场映射、实际持仓覆盖、到期时间，以及既有机会/展期定价与保证金证据，保持现有查询、缓存与刷新策略。
- [ ] 只有来源支持的子账户、完整当前 Boros 持仓和有效到期证明至少 14 天，才暂停除到期天数外的适用展期检查；部分持仓或历史覆盖标志不能替代这个门槛。
- [ ] 暂停状态单独显示且不计作 OK，已知异常和缺失证据不会因过滤列表或钱包切换被清除。
- [ ] 展期候选必须匹配实际规模、对应 venues 和更晚到期；净 APR 使用其原有 notional 口径，深度覆盖以既有可执行报价证据为准，不用 mid 或资本 APR 替代。
- [ ] 共存阶段所需保证金和事后覆盖只接受实际验证的现有评估；来源缺失时保留 UNKNOWN，不因机会存在而假定可以展期。
- [ ] 按实际永续及相应有效 Boros 腿判断资金费缺口；数量和时长分别验证，起始时间来自已有可信历史，访问页面不得重置起点或伪造连续监控历史。
- [ ] 缺少缺口时长或保证金证据时仍展示独立有效的数量/到期信息及明确缺失原因；没有完整空仓证据时不得直接清零。
- [ ] 页面/API 合成场景覆盖临近/已到期、14 天边界、缺元数据、部分持仓、不支持子账户、错误 venue、无匹配报价、缺时长和旧状态无法核验；规则结果与 Python 语义一致。
- [ ] Risk 仅展示既有只读报价/评估或可验证证据，不因轮询调用执行、授权或产生提交标识的交易操作；相关离线检查通过。
