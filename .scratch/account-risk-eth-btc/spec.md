# ETH/BTC 账户级风险报告

Status: ready-for-agent
Type: task
Created: 2026-10-12

## Problem Statement

用户需要知道 Gate CrossEx 和 Boros 账户的整体风险，而当前风险模型把多数关键指标限制为单组 Binance–Hyperliquid ETH 四腿组合。实际账户已有 Binance–Hyperliquid、OKX–Hyperliquid 两组资金费仓位、不同到期日，以及共享的 Hyperliquid 永续仓位。持仓证据完整时仍出现六项 UNKNOWN，用户无法区分真实证据缺口和模型不支持。

目前永续数量校验排除 OKX，利率估值、资金费腿匹配、期限及亏损比例依赖单组配对。价格盈亏还存在把共享 Hyperliquid 全仓与部分 Binance 持仓相加、遗漏 OKX 的口径问题。最近24小时净结算为正时，续航没有有限数值，又被当成证据缺失。

用户已确认报告应支持 ETH、BTC，按 Gate CrossEx、Boros 各自账户汇总风险和当前浮盈亏。Boros 的不同抵押池不能互相补足，账户总盈利或总净流入不能掩盖某个池的保证金不足或持续净流出。

## Solution

提供账户级、只读、共享判定的风险报告。分别展示 Gate CrossEx 和 Boros 的权益、当前浮盈亏、当前浮亏占权益比例以及适用风险状态。保留账户保证金、负债、执行残留、服务和监控证据检查。

Gate CrossEx 的 ETH、BTC 永续价格净敞口分别规范化并估值，绝对美元敞口合计后除以 Gate 账户权益；不同币种不互相抵消。逐来源、方向汇总有效资金费腿，与对应永续腿核对数量，分别展示缺口和过覆盖；不再进行组合期限配对，不因永续价格净敞口为零而宣称资金费对冲完整。

Boros 按全仓池、逐仓池分别判断健康度、可用抵押品和净流出续航，账户报告汇总告警及证据缺口。净结算流入为正、流出为负，同时展示原币分项和美元汇总；完整窗口流入或零流出时续航为 NA，完整净流出窗口才计算续航。

风险页、独立监控和只读报告使用同一判定。修复目标是消除模型造成的 UNKNOWN，并正确保留真实 UNKNOWN、WARNING 和 CRITICAL。

## User Stories

1. As an 账户持有人, I want 同时检查 ETH 和 BTC 持仓, so that 两种币的风险都进入报告。
2. As an 账户持有人, I want 分别看到 Gate CrossEx 与 Boros 账户状态, so that 我知道风险发生在哪里。
3. As an 账户持有人, I want 看到每个账户完整权益, so that 风险比例使用正确分母。
4. As an 账户持有人, I want 看到每个账户当前浮盈亏, so that 我能判断当前估值压力。
5. As an 账户持有人, I want 两账户浮盈亏不互相抵消, so that 一个账户盈利不会掩盖另一账户亏损。
6. As an 账户持有人, I want 当前浮亏占权益的比例, so that 我能按已确认阈值识别估值风险。
7. As an 账户持有人, I want 历史已实现收益与当前浮盈亏分开, so that 历史盈利不会误作当前缓冲。
8. As an 账户持有人, I want 资金费和手续费避免重复计入, so that 权益与盈亏解释一致。
9. As an 账户持有人, I want OKX ETH 永续被正确识别, so that 已支持合约不会导致虚假的 UNKNOWN。
10. As an 账户持有人, I want ETH 和 BTC 分别显示净数量, so that 我能看见具体资产的永续价格净敞口。
11. As an 账户持有人, I want 按正确合约乘数和标的单位计算数量, so that 不同合约的持仓可以核对。
12. As an 账户持有人, I want 不同币种的美元净敞口不互相抵消, so that ETH 多头与 BTC 空头不会被判为零风险。
13. As an 账户持有人, I want 残余敞口绝对美元值合计及其权益比例, so that 我能评估账户规模下的残余风险。
14. As an 账户持有人, I want 同一来源的 Boros 多腿与共享永续按方向汇总核对, so that 共享 Hyperliquid 仓位不会重复计入。
15. As an 账户持有人, I want 资金费缺口独立展示, so that 净数量中性不会掩盖资金费对冲不完整。
16. As an 账户持有人, I want 资金费过覆盖独立展示, so that 多余利率腿不会被解释为额外保证金。
17. As an 账户持有人, I want 有效资金费腿按标的、来源和方向汇总后与永续腿匹配数量, so that 不同到期日不会产生额外的配对限制。
18. As an 账户持有人, I want 真实错方向和过期腿仍被识别, so that 数量匹配不会把无效资金费腿计作覆盖。
19. As an 账户持有人, I want Boros 全仓池和逐仓池分别检查健康度, so that 不可互通的资金不会被合并成安全缓冲。
20. As an 账户持有人, I want 账户总额之外还能看到异常池, so that 我可以定位需要关注的抵押品。
21. As an 账户持有人, I want 看到最近24小时净结算的正负号, so that 我能区分到账和消耗。
22. As an 账户持有人, I want ETH、BTC 及相关抵押币的原币净结算分项, so that 不同单位不会被直接相加。
23. As an 账户持有人, I want USDT/USDC 按 1:1 USD 汇总、其他抵押币按有效价格换算的净结算, so that 我能理解账户整体现金流。
24. As an 账户持有人, I want 净流入与零流出时续航显示 NA, so that 不适用不会被伪装成无限生存时间或缺失证据。
25. As an 账户持有人, I want 流出池单独显示历史续航, so that 账户总净流入不会掩盖该池消耗。
26. As an 账户持有人, I want 不完整结算分页仍显示 UNKNOWN, so that 部分数据不会产生假的正常状态。
27. As an 账户持有人, I want 缺失、过期和身份不匹配的证据保留 UNKNOWN, so that 报告不会无依据判安全。
28. As an 账户持有人, I want 其他非零持仓触发覆盖不完整提示, so that ETH/BTC 范围不会冒充完整账户风险。
29. As an 账户持有人, I want 权益为零或负数时明确风险与不可计算比例, so that 公式不会产生假的 OK。
30. As an 账户持有人, I want 可配置且有单位的阈值, so that 告警符合已确认口径。
31. As an 账户持有人, I want 看到告警原因和缺失证据, so that 我能区分真实异常与不可验证状态。
32. As an 账户持有人, I want 切换账户或钱包后隔离旧证据, so that 其他账户的正常结果不会污染本账户。
33. As an 账户持有人, I want 既有严重告警在缺失恢复证据时保持, so that 模型升级不会静默清除风险。
34. As an 账户持有人, I want 风险页、监控和只读脚本判定一致, so that 不同入口不会给出矛盾结论。
35. As an 账户持有人, I want 每次报告显示快照时间和覆盖状态, so that 我知道数据的时效与适用范围。
36. As an 账户持有人, I want 查询不下单、不转账、不改状态或发送通知, so that 分析本身不会改变账户。

## Implementation Decisions

- 扩展现有风险输入、证据契约和共享判定层，复用现有持仓、抵押品、资产账本和结算事件读取；不为风险页另建交易或采集流程。
- 风险主体是同一终端配置下的 Gate 账户和所选 Boros 钱包/子账户；证据分别携带账户身份、标的、抵押币、池身份、单位、观察时间及完整性。仅依靠旧 ETH 单池标识不足以证明扩展后的账户覆盖。
- 普通资产视图已有多币种、多池数据；扩展风险专用证据覆盖 ETH/BTC 活跃持仓及相关全仓池、逐仓池，避免把普通资产视图覆盖误当成风险证据覆盖。
- 账户权益取完整账户口径，支持范围内的持仓浮盈亏必须完整。任何其他非零持仓触发持仓覆盖不完整及相关 UNKNOWN；完整账户权益、保证金和负债仍展示，不删除已知值或已触发告警。
- Gate 当前浮盈亏使用经核实语义的账户未实现盈亏；若用持仓加总作为来源，必须证明完整覆盖并与账户字段一致。Boros 当前浮盈亏使用账户相关池全部持仓的可验证当前估值盈亏，保证金权益与估值口径需明确，不能重复加回已含在权益内的盈亏。
- 各账户当前浮亏比例为 max(0, -账户当前浮盈亏) / 账户当前权益；两账户分别计算。账户内部持仓盈亏按用户确认的账户口径汇总，不分摊共享永续的组合盈亏。
- 正权益且证据完整时才使用普通比例公式。权益为零或负数时显式报告异常，健康检查不得判 OK；比例显示不可计算并保留具体原因，禁止填零或无穷大。
- 原组合价格亏损/到期利润指标不再作为本报告账户风险的必需指标。原单组利差变化也不再是账户估值检查的证据依赖；使用账户当前浮亏比例替代账户级估值告警。到期利润和组合利差如已有其他视图，可保留原用途但不冒充账户安全度量。
- ETH、BTC 永续数量按标准化合约身份、标的和乘数计算。白名单来自项目已支持的合约映射，纳入 OKX；未知合约、重复或数量矛盾仍为 UNKNOWN。
- 永续价格净敞口仅描述永续仓位，不包含抵押品自身的价格敞口。分别显示 ETH/BTC 有符号净数量；残余敞口美元合计为各币净敞口绝对美元值之和，除以完整 Gate 账户权益。不允许跨币抵消。
- USDT、USDC 均固定按 1:1 换算 USD，不依赖额外的稳定币汇率证据。其他币种仍需有效报价。永续残余敞口估值沿用现有实现：同一标的取相关永续仓位中最高的有效标记价，美元敞口为净标的数量绝对值乘该价格；展示价格来源、换算时点及稳定币 1:1 假设。相关仓位价格缺失或过期时保留 UNKNOWN，不替代为零。
- Boros 数量必须携带原单位及抵押币/标的身份。不得把抵押币 sizeToken 直接认成标的数量；使用经验证的市场数量语义和现有单位换算，无法证明换算时保留 UNKNOWN。
- 按标的、资金费来源和方向汇总有效资金费腿的标准化数量，与对应永续腿数量匹配，支持一个来源多到期利率腿共享一个永续仓位。资金费缺口、资金费过覆盖与永续价格净敞口分别报告；不能因账户净敞口为零而跳过方向和覆盖校验。
- 不进行组合期限配对，不要求不同来源的利率腿到期日相同，也不要求每个到期日的多空数量平衡。到期日仅用于判断资金费腿有效性及保留到期/展期倒计时；过期腿不得计入有效数量覆盖。无法解释的剩余数量、错方向或过期腿仍报告真实异常；有效性证据不足保持 UNKNOWN。
- 资金费数量差须保留经验证单位的既有阈值/容差，不把 ETH 数量阈值原值复制给 BTC。规范化或适用阈值证据不足时不得宣称匹配通过；交易精度容差不得用来掩盖真实缺口。
- Boros 账户权益和浮盈亏可以美元汇总；保证金健康、可用抵押品和续航按每个独立全仓池/逐仓池计算。异常池及其身份必须可定位，健康池的资金不抵消异常池。
- 净结算窗口为最近24小时，使用完整、去重、身份一致的带符号结算事件；结算费按已有事件语义已包含，不再扣一次。原币分项按抵押币/池显示，美元汇总中 USDT/USDC 按 1:1、其他币种使用当前可验证报价，标注换算时点和假设。
- 完整净流入或零流出窗口的续航为 NA；只有完整净流出窗口才以同池可用抵押品 / 最近24小时净流出计算历史续航。NA 是适用性状态，不是假零、不代表完整数据缺失、不承诺未来没有消耗。
- 账户净流入为正时仍评估每个流出池。任何活跃池的窗口、价格或余额证据缺失，使相应汇总不可验证；已知原币数据和真实告警仍保留。
- 已确认的可配置默认阈值：账户浮亏比例 >10% WARNING、>20% CRITICAL；残余敞口美元合计/Gate 权益 >0.1% WARNING、>1% CRITICAL。使用严格大于；这些不是交易所强平线。逐池净流出续航沿用现有 <7天 WARNING、<2天 CRITICAL。
- 共享风险判定取消恢复滞回。证据完整且可验证时，首次触发、升级、降级和恢复均按当前值与同一有效阈值直接比较，不因历史告警调整边界；旧 recoveryMarginFraction 不再参与风险状态判定。例如浮亏比例恰为20%时为 WARNING，恰为10%时不触发该比例告警，不受此前 CRITICAL 影响。缺失恢复证据时保留既有未解决 CRITICAL 的规则继续适用；监控调度和通知去重保持既有行为。
- 保留既有保证金、负债、执行未对冲残留、数据时效、服务、监控和通知证据规则。不同风险可以并存；账户汇总必须同时保留告警与覆盖缺口，不因总体状态是 WARNING/CRITICAL 而隐藏 UNKNOWN。
- 适配风险设置、指标单位、状态历史和 producer scope 的版本变化。旧配置中失效的组合阈值不得误用于新账户比例；新默认值及有效配置需可见。旧 UNKNOWN 可以由完整新证据解决，旧 CRITICAL 不得因改名、删指标或改变主体而静默清除；缺失可靠兼容或恢复证据时显式保留未解决严重状态。
- 风险页、共享只读报告、监控消费者和只读脚本同步识别 ETH/BTC、多池、NA、新指标与新身份。共享判定保持唯一来源，消费者不得自行重算一套风险公式。
- 只读报告保持认证、身份隔离、时间/覆盖契约、输出脱敏及既有退出码语义。巡检不取得监控锁，不写心跳/状态/队列，不发送测试通知，不触碰交易或转账。

## Testing Decisions

- 主验收边界采用现有共享风险报告 GET 接口，用户已确认。离线通过 app.inject() 调用真实报告组合与判定，上游数据使用现有 fixtures/stubs；不 listen、不访问真实交易所、不新增测试专用业务接口。
- 好的测试断言外部可见指标值、单位、覆盖、NA/UNKNOWN、状态、原因及汇总行为；不只断言函数调用、分支实现或 API 结果与同一公式自比较。
- 复用现有风险报告服务端测试的认证、过期、故障、账户隔离和历史 CRITICAL 场景，构造独立预期值验证新账户公式。
- 核心固定夹具包含 Binance/OKX 多头与共享 Hyperliquid 空头、两组不同期限；证明无重复计数，完整已支持持仓不再因单组限制而 UNKNOWN。
- ETH/BTC 等美元相反净敞口仍产生两币绝对美元值合计；验证合约乘数、抵押币不同于标的、报价缺失和未知合约。以不同交易所标记价验证同标的取最高有效价；验证 USDT/USDC 无额外汇率证据仍按 1:1 USD 计算，其他币种缺价保留 UNKNOWN。
- 验证两账户浮盈亏不抵消、历史已实现收益不混入、费用不重复扣除、账户内部浮盈亏正确汇总。覆盖零浮亏、严格阈值相等、超过阈值、零/负权益；分别覆盖无历史状态和从 WARNING/CRITICAL 回落的路径，证明完整同一快照的状态不受历史状态或 recoveryMarginFraction 影响。证据缺失时仍保留未解决 CRITICAL。
- 验证 ETH/BTC 多个全仓池与逐仓池：账户总盈利或总净流入时，单池保证金不足/流出仍可触发告警。价格缺失时美元汇总 UNKNOWN，原币已知数据保留。
- 结算覆盖正、零、负、部分分页、重复事件、错误钱包/子账户/池、未来/过期证据和跨币单位。只有完整非流出窗口续航为 NA，真实净流出窗口产生有限历史续航。
- 资金费检查覆盖漏腿、错方向、过覆盖、过期腿、不同到期日以及无法解释的残量，不能只验证账户净数量。同一标的/来源/方向的有效数量匹配时，不因不同来源到期日不一致或单个到期日多空不平衡而报错；过期腿不能补足有效资金费数量。
- 非零不支持币种触发账户持仓覆盖缺口；已知告警、完整账户负债和保证金仍被保留。
- 复用风险规则边界及跨消费者一致性测试，验证风险页、监控与只读脚本对同一快照的值、NA、阈值、状态、原因和计数一致。
- 验证旧单池配置/历史状态兼容、有效阈值展示、账户切换隔离；缺失恢复证据时既有 CRITICAL 不被迁移或改名清除。
- 验证只读脚本的脱敏、退出码和无副作用；监控既有调度、锁、状态、心跳和通知行为保持。验证不得通过发送真实通知实现。
- 完成相关服务端/共享/UI/Python 离线测试、项目 verify 与生产 web build。增加真实浏览器验收，检查两账户、多币、多池、正负净结算、NA、证据缺口和异常池定位的显示。
- 使用实际账户只读快照完成运行时验证。实际无 BTC 仓位时明确 BTC 以离线夹具验收，不声称实盘 BTC 验证完成。源代码/构建成功不能代替运行时证明。
- 若运行时验证需重载服务，先按项目现有安全流程验证无活跃 deal 和未完成订单；本规格不授权绕过该边界或直接重启交易服务。

## Out of Scope

- 实现 ETH/BTC 之外的新标的风险模型；发现其非零持仓时只报告覆盖缺口。
- 自动下单、平仓、补腿、转账、追加资金、借款、授权和自动展期。
- 改变 deal 引擎、maker 报价、执行或恢复行为，或增加新的交易经济性门槛。
- 组合级共享永续盈亏分摊、逐组合到期利润风控，以及以账户盈亏反推出成交归属。
- 重建组合期限归属、跨来源到期日配对和逐到期日多空数量平衡检查。
- 以当前标记价替代真实成交退出成本，或以永续价格净敞口表示抵押品价格风险。
- 重建历史账本、修改既有历史收益口径，或增加预测性生存天数保证。
- 真实下单测试、测试通知、服务安装及未经另行授权的账户/配置操作。
